export const enRegions = Object.entries(en.regionOrders);
export const regionsWith = (order) =>
  enRegions
    .filter(([, regionOrder]) => regionOrder === order)
    .map(([tag]) => tag);

fechita's language data is split into one module per locale, under
`fechita/locales/<tag>`. Each one holds the month names, weekday names, AM/PM
and day period words, era names and usual date order of one language, taken
from Unicode CLDR 48. Load the ones you need and pass them to
[`withLocales`](../with-locales/) or [`parseDateWith`](../parse-date-with/).

The default entry, `fechita`, already includes all of them. You only need
these imports with `@aleksejdix/fechita/core`.

## Import one locale

```ts
import { withLocales } from "@aleksejdix/fechita/core";
import { fr } from "@aleksejdix/fechita/locales/fr";

const { parseDate } = withLocales({ fr });

parseDate("mardi 31 mars 2026"); // → valid: 31 March 2026
```

The path ends in the locale tag, and the export has the same name:
`@aleksejdix/fechita/locales/de` exports `de`, `@aleksejdix/fechita/locales/ja` exports `ja`.

Tags with a hyphen are exported in camel case. Give them their real tag as
the key, so that the `locale` option finds them:

| Import                                                           | Pass as                   |
| ---------------------------------------------------------------- | ------------------------- |
| `import { zhHant } from "@aleksejdix/fechita/locales/zh-Hant"`   | `{ "zh-Hant": zhHant }`   |
| `import { srLatn } from "@aleksejdix/fechita/locales/sr-Latn"`   | `{ "sr-Latn": srLatn }`   |
| `import { hiLatn } from "@aleksejdix/fechita/locales/hi-Latn"`   | `{ "hi-Latn": hiLatn }`   |
| `import { kkArab } from "@aleksejdix/fechita/locales/kk-Arab"`   | `{ "kk-Arab": kkArab }`   |
| `import { yueHans } from "@aleksejdix/fechita/locales/yue-Hans"` | `{ "yue-Hans": yueHans }` |

## Regions come with the language

There is one module per language, not per country. The regional date orders
are inside it. `en` knows that `en-US` writes month first, `en-GB` writes day
first and `en-CA` writes year first.

```ts
import { en } from "@aleksejdix/fechita/locales/en";

const { parseDate } = withLocales({ en });

parseDate("04/05/2026", { locale: "en-US" }); // → 5 April 2026
parseDate("04/05/2026", { locale: "en-GB" }); // → 4 May 2026
```

## See the list in code

`@aleksejdix/fechita/locales/all` exports every locale in one object, keyed by tag:

```ts
import { allLocales } from "@aleksejdix/fechita/locales/all";

Object.keys(allLocales).length; // → 104
Object.keys(allLocales); // → ["af", "ak", "am", …, "zh-Hant", "zu"]
```

`withLocales(allLocales)` gives the same results as the default `parseDate`.
Importing it puts all the data in your bundle, so use it for tools and
tests, not to save bytes.

## What a locale contains

Each module is plain data, safe to inspect:

| Field          | What it is                                                                      |
| -------------- | ------------------------------------------------------------------------------- |
| `tag`          | The locale tag, e.g. `"de"` or `"zh-Hant"`.                                     |
| `order`        | The usual order of numeric dates: `"DMY"`, `"MDY"` or `"YMD"`.                  |
| `regionOrders` | Regions whose order differs from `order`, e.g. `{ "en-GB": "DMY", … }` in `en`. |
| `months`       | The names of each month, January first, in full and short forms.                |
| `weekdays`     | The names of each weekday, Sunday first.                                        |
| `dayPeriods`   | AM and PM words, and words like "evening" with the hours they cover.            |
| `eras`         | The words for before and after the common era: `"v. Chr."`, `"n. Chr."`.        |
