import { divideWith, periodWith } from "@aleksejdix/minuta/core";
import { nativeUnits } from "@aleksejdix/minuta/native";
import { luxonUnits } from "@aleksejdix/minuta/luxon";
import Timeline from "../../../../components/diagrams/Timeline.astro";

export const weeksOfMarch = (units) =>
  divideWith(units, periodWith(units, new Date(2026, 2, 1), "month"), "week");

Units computed with [Luxon](https://moment.github.io/luxon/), the date
library built around immutable `DateTime` objects. Dates are read in Luxon's
default time zone, which is the computer's zone unless you change it.

```ts
import { luxonUnits } from "@aleksejdix/minuta/luxon";
```

```ts
luxonUnits(options?)
```

## Example

```ts
import { luxonUnits } from "@aleksejdix/minuta/luxon";
import { withUnits } from "@aleksejdix/minuta/core";

const time = withUnits(luxonUnits({ weekStartsOn: "sunday" }));

time.period(new Date(2026, 2, 18), "week");
// → { start: Sun Mar 15 00:00, end: Sat Mar 21 23:59:59.999, unit: "week" }
```

minuta takes and returns plain `Date` objects, also with Luxon. Convert at
the edges: `DateTime.fromJSDate(period.start)` and `dateTime.toJSDate()`.

## When to choose it

- Your app already uses Luxon and you want its rules for months, days and
  clock changes.

The results are the same as with [`nativeUnits`](../native-units/).

`Date`. The bars are the same, down to the cut pieces at the month's edges:

## Install

```sh
npm install @aleksejdix/minuta luxon
```

minuta is tested with Luxon 3. Luxon is listed as an optional dependency of
minuta, so npm may install it already.

## Parameters

| Name      | What it is                                                 |
| --------- | ---------------------------------------------------------- |
| `options` | Optional. Week start and weekend, see [Options](#options). |

## Options

| Option         | Default                  | What it does                                                                               |
| -------------- | ------------------------ | ------------------------------------------------------------------------------------------ |
| `weekStartsOn` | `"monday"`               | The first day of the week: `"sunday"` … `"saturday"`, or 0 (Sunday) … 6 (Saturday).        |
| `weekend`      | `["saturday", "sunday"]` | The days that [`isWeekendWith`](../../minuta-calendar/is-weekend-with/) counts as weekend. |

There is no time zone option.

## Returns

The units: a spec for each of `year`, `quarter`, `month`, `week`, `day`,
`hour`, `minute` and `second`, plus `timeZone` (the computer's zone, e.g.
`"Europe/Zurich"`), `weekStartsOn` (a number) and `weekend` (numbers).

## Luxon's default zone

:::caution
Do not change `Settings.defaultZone` of Luxon when you use these units.
The specs compute in Luxon's default zone, but the `timeZone` setting of the
units still says the computer's zone. Functions that read that setting
then disagree with the specs.
:::

On a computer in Europe/Zurich, with `Settings.defaultZone = "America/New_York"`:

```ts
const units = luxonUnits();

units.timeZone; // → "Europe/Zurich", although the days are New York days
dayGridWith(units, new Date("2026-03-08T17:00:00Z")).periods.length; // → 23 (New York's short day)
dayGridWith(units, new Date("2026-03-08T17:00:00Z")).gapHour; // → undefined (should be 2)
```

For a fixed time zone, use [`dateFnsTzUnits`](../date-fns-tz-units/).
