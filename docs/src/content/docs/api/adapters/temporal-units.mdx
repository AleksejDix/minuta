import { divideWith, periodWith } from "@aleksejdix/minuta/core";
import { nativeUnits } from "@aleksejdix/minuta/native";
import { temporalUnits } from "@aleksejdix/minuta/temporal";
import Timeline from "../../../../components/diagrams/Timeline.astro";

export const weeksOfMarch = (units) =>
  divideWith(units, periodWith(units, new Date(2026, 2, 1), "month"), "week");

Units computed with [Temporal](https://tc39.es/proposal-temporal/docs/), the
new date API for JavaScript. Where the runtime has no Temporal yet,
[`temporalReady`](../temporal-ready/) loads `@js-temporal/polyfill` first.
Dates are read in the time zone of the computer the code runs on.

```ts
import { temporalUnits } from "@aleksejdix/minuta/temporal";
```

```ts
temporalUnits(options?)
```

## Example

```ts
import { temporalUnits } from "@aleksejdix/minuta/temporal";
import { withUnits } from "@aleksejdix/minuta/core";

const time = withUnits(temporalUnits({ weekStartsOn: "sunday" }));

time.period(new Date(2026, 2, 18), "week");
// → { start: Sun Mar 15 00:00, end: Sat Mar 21 23:59:59.999, unit: "week" }
```

minuta takes and returns plain `Date` objects, also here. Temporal does the
calendar arithmetic for days, months, quarters and years inside the units.

## When to choose it

- You are moving your app to Temporal and want minuta to use the same
  arithmetic.

The results are the same as with [`nativeUnits`](../native-units/). The
units do **not** use Temporal's time zones: they work in the computer's
zone like `nativeUnits`. For a fixed zone, use
[`dateFnsTzUnits`](../date-fns-tz-units/).

## Install

```sh
npm install @aleksejdix/minuta @js-temporal/polyfill
```

The polyfill is only needed where the runtime has no Temporal (Safari, Node
24). minuta is tested with `@js-temporal/polyfill` 0.5. It is an optional
peer dependency of minuta, so install it yourself when you need it.

## Parameters

| Name      | What it is                                                 |
| --------- | ---------------------------------------------------------- |
| `options` | Optional. Week start and weekend, see [Options](#options). |

## Options

| Option         | Default                  | What it does                                                                               |
| -------------- | ------------------------ | ------------------------------------------------------------------------------------------ |
| `weekStartsOn` | `"monday"`               | The first day of the week: `"sunday"` … `"saturday"`, or 0 (Sunday) … 6 (Saturday).        |
| `weekend`      | `["saturday", "sunday"]` | The days that [`isWeekendWith`](../../minuta-calendar/is-weekend-with/) counts as weekend. |

There is no time zone option.

## Returns

The units: a spec for each of `year`, `quarter`, `month`, `week`, `day`,
`hour`, `minute` and `second`, plus `timeZone` (the computer's zone, e.g.
`"Europe/Zurich"`), `weekStartsOn` (a number) and `weekend` (numbers).

## Native Temporal first, the polyfill only where it is missing

minuta reads `globalThis.Temporal` when it computes, never at import:

- If the runtime has Temporal (Chrome and Edge 144+, Firefox 139+, Node
  26+), it is used and nothing else is loaded.
- If not, `await temporalReady()` once, before anything renders. It loads the
  polyfill in its own chunk and installs it on `globalThis`.
- Computing with neither throws an error that names `temporalReady()`.

Importing `@aleksejdix/minuta/temporal` changes nothing, and the polyfill is
not in your bundle unless you call `temporalReady()`. See
[`temporalReady`](../temporal-ready/) for an app setup.
