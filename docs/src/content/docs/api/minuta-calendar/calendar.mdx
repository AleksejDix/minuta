Binds the five calendar functions to your units, so you no longer pass the
units on every call.

```ts
import { calendar } from "@aleksejdix/minuta/calendar";
```

```ts
calendar(units);
```

## Example

```ts
import { calendar } from "@aleksejdix/minuta/calendar";
import { createUnits } from "@aleksejdix/minuta/core";
import { period } from "@aleksejdix/minuta";

const grids = calendar(
  createUnits({ weekStartsOn: "sunday", weekend: ["friday", "saturday"] })
);

const march = Temporal.PlainDate.from("2026-03-15");
grids.monthGrid(march).periods.length; // → 42
grids.monthGrid(march).periods[0].start; // → 2026-03-01, a Sunday
grids.isWeekend(period(Temporal.PlainDate.from("2026-03-20"), "day")); // → true (a Friday)
```

This is the grid `grids.monthGrid` gives for March 2026: it starts on Sunday
Mar 1 because the units start weeks on Sunday.

## With the operations

Bind the operations with [`withUnits`](../../minuta-core/with-units/) and
the calendar with `calendar`, from the same units:

```ts
import { createUnits, withUnits } from "@aleksejdix/minuta/core";

const units = createUnits({ weekStartsOn: "sunday" });
const time = withUnits(units);
const grids = calendar(units);

grids.monthGrid(time.next(time.period(march, "month")).start); // April's grid
```

## Parameters

| Name    | What it is                                                                                                                                                         |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `units` | The units to compute with, usually [`createUnits()`](../../minuta-core/create-units/). Keep the full set: the grids read `weekStartsOn`, `weekend` and `timeZone`. |

## Returns

An object of the five functions above, without their `units` argument.
