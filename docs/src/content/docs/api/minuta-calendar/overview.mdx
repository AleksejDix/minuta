`@aleksejdix/minuta/calendar` builds what a calendar screen needs: the days of a month
view, the weeks of a year, the hours of a day, and whether a day is on the
weekend.

```ts
import { calendar, monthGridWith } from "@aleksejdix/minuta/calendar";
```

It is a separate entry point, so it costs nothing in your bundle until you
import it.

## Functions

| Function                               | What it does                                                      |
| -------------------------------------- | ----------------------------------------------------------------- |
| [`monthGridWith`](../month-grid-with/) | The 42 days (6 weeks) of a month view.                            |
| [`yearGridWith`](../year-grid-with/)   | The whole weeks that cover a year.                                |
| [`dayGridWith`](../day-grid-with/)     | The real hours of a day: 23, 24 or 25, with the DST hours marked. |
| [`isWeekdayWith`](../is-weekday-with/) | Whether a period touches only working days.                       |
| [`isWeekendWith`](../is-weekend-with/) | Whether a period touches only weekend days.                       |
| [`calendar`](../calendar/)             | All five, bound to your units: `calendar(units)`.                 |

## Units first

Every function takes **units** as its first argument. Units are the rules
for each unit of time (year, month, week, day, hour, …), made by
`createUnits()`. They also carry three settings:

- the first day of the week (`weekStartsOn`, Monday unless set),
- the weekend days (`weekend`, Saturday and Sunday unless set),
- the time zone (`timeZone`).

The grids and checks follow these settings. A Sunday-first calendar is just
other units:

```ts
import { monthGridWith } from "@aleksejdix/minuta/calendar";
import { createUnits } from "@aleksejdix/minuta/core";

const march15 = Temporal.PlainDate.from("2026-03-15");

monthGridWith(createUnits(), march15).periods[0];
// → { start: 2026-02-23, end: 2026-02-24, unit: "day" }, a Monday

monthGridWith(createUnits({ weekStartsOn: "sunday" }), march15).periods[0];
// → { start: 2026-03-01, end: 2026-03-02, unit: "day" }, a Sunday
```

which days the 6 rows hold:

## Or bind the units once

Passing the units every time gets old. Bind them once with `calendar` and
call the functions without them:

```ts
import { calendar } from "@aleksejdix/minuta/calendar";
import { createUnits } from "@aleksejdix/minuta/core";
import { period } from "@aleksejdix/minuta";

const grids = calendar(createUnits({ weekStartsOn: "sunday" }));

grids.monthGrid(Temporal.PlainDate.from("2026-03-15")); // same as monthGridWith(units, date)
grids.isWeekend(period(Temporal.PlainDate.from("2026-03-21"), "day")); // → true
```

## Key ideas

- **Stable grids.** A month grid always has 42 days, so a month view never
  changes height. A year grid is made of whole weeks.
- **Everything is a period.** Grid cells are ordinary periods
  (`{ start, end, unit }`), so all other functions work on them.
- **Real time.** A day cell is a calendar day, even when it has 23 or 25
  hours. A day grid lists the hours that really happen.
- **Time zones come from the units.** With
  `createUnits({ timeZone: "Asia/Tokyo" })`, an `Instant` falls on Tokyo's
  day and a day grid has Tokyo's hours. A day grid for a `ZonedDateTime` has
  the hours of that moment's zone.
