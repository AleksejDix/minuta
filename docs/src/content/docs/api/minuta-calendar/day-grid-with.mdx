import { createUnits } from "@aleksejdix/minuta/core";
import { instant } from "../../../../components/temporal";
import { range } from "@aleksejdix/minuta";
import { dayGridWith } from "@aleksejdix/minuta/calendar";
import { divideWith } from "@aleksejdix/minuta/core";
import Timeline from "../../../../components/diagrams/Timeline.astro";

export const newYork = createUnits({ timeZone: "America/New_York" });
export const spring = dayGridWith(newYork, instant("2024-03-10T12:00:00Z"));
export const autumn = dayGridWith(newYork, instant("2024-11-03T12:00:00Z"));
export const fullDay = (grid) =>
  divideWith(
    newYork,
    range(grid.periods[0].start, grid.periods[0].start.add({ hours: 24 })),
    "hour"
  );

Get the real hours of one day, each labelled with the hour on the clock.
Most days have 24 hours. The day the clocks go forward has 23, and the day
they go back has 25.

```ts
import { dayGridWith } from "@aleksejdix/minuta/calendar";
```

```ts
dayGridWith(units, value);
```

## Example

```ts
import { dayGridWith } from "@aleksejdix/minuta/calendar";
import { createUnits } from "@aleksejdix/minuta/core";

// With the runtime in Europe/Zurich
const grid = dayGridWith(createUnits(), Temporal.PlainDate.from("2026-06-01"));

grid.periods.length; // → 24
grid.periods[0]; // → { start: 2026-06-01T00:00, end: 2026-06-01T01:00, unit: "hour", hour: 0 }
grid.gapHour; // → undefined
grid.ambiguousHour; // → undefined
```

## Parameters

| Name    | What it is                                                                                              |
| ------- | ------------------------------------------------------------------------------------------------------- |
| `units` | The units to compute with, e.g. `createUnits()` or `createUnits({ timeZone })`. Needs `day` and `hour`. |
| `value` | The day you want: a `PlainDate`, or any `PlainDateTime`, `ZonedDateTime` or `Instant` inside it.        |

## Returns

An object with three fields:

- `periods` — one hour period per real hour of the day, in order. Each has
  `start`, `end` (`ZonedDateTime`s) and `unit` like any period, plus `hour`:
  the hour on the clock, 0 to 23.
- `gapHour` — the clock hour that does not exist that day because the clocks
  jumped forward, or `undefined`.
- `ambiguousHour` — the clock hour that happens twice that day because the
  clocks went back, or `undefined`.

## Clocks going forward: 23 hours

Many time zones have daylight saving time (DST). On one night in spring the
clocks jump forward one hour. In Europe/Zurich on Mar 29 2026 the clock goes
from 01:59:59 straight to 03:00. The hour 2:00 never happens.

```ts
// With the runtime in Europe/Zurich
const spring = dayGridWith(
  createUnits(),
  Temporal.PlainDate.from("2026-03-29")
);

spring.periods.length; // → 23
spring.periods.map((slot) => slot.hour);
// → [0, 1, 3, 4, 5, …, 23]
spring.gapHour; // → 2
```

New York does the same, one hour earlier in the night: on Mar 10 2024 its
clocks jump from 1:59 to 3:00. Each bar below is one period of the grid.
The grid ends one hour before 24 hours after midnight would:

## Clocks going back: 25 hours

On one night in autumn the clocks go back one hour, so one clock hour happens
twice. In Europe/Zurich on Oct 25 2026 the hour 2:00 comes once in summer
time and once more in winter time. Both are in the grid, as two different
periods with `hour: 2`.

```ts
const autumn = dayGridWith(
  createUnits(),
  Temporal.PlainDate.from("2026-10-25")
);

autumn.periods.length; // → 25
autumn.periods.map((slot) => slot.hour);
// → [0, 1, 2, 2, 3, 4, …, 23]
autumn.ambiguousHour; // → 2
autumn.periods[2]; // → 02:00+02:00 – 02:00+01:00, summer time (CEST), hour 2
autumn.periods[3]; // → 02:00+01:00 – 03:00+01:00, winter time (CET),  hour 2
```

In New York the clocks went back on Nov 3 2024, and the hour 1:00 came
twice. The grid has 25 bars and runs one hour past 24 hours after midnight:

Use `gapHour` and `ambiguousHour` to show a hint in a day view, e.g. "2:00
happens twice tonight".

## Another time zone

The hours are computed and labelled in the zone of a `ZonedDateTime` you
pass, else in the `timeZone` of the units. `createUnits()` uses the
runtime's zone. To show a day in another zone, set one with
[`createUnits`](../../minuta-core/create-units/):

```ts
const newYork = createUnits({ timeZone: "America/New_York" });
const grid = dayGridWith(newYork, Temporal.PlainDate.from("2024-03-10"));

grid.periods.length; // → 23
grid.gapHour; // → 2
grid.periods[0].start.toString(); // → "2024-03-10T00:00:00-05:00[America/New_York]"
```

Or pass a moment in that zone:
`dayGridWith(createUnits(), Temporal.ZonedDateTime.from("2024-03-10T12:00[America/New_York]"))`
gives the same 23 hours. If you build your own units without a `timeZone`,
the runtime's zone is used.

:::caution
A few zones move their clocks by 30 minutes, such as Australia/Lord_Howe.
On those days the hours do not line up with the clock, and the grid can
contain a 30-minute slot. `gapHour` and `ambiguousHour` are not reliable
there.
:::

## Errors

`dayGridWith` throws a `RangeError` starting with `UNIT_NOT_SUPPORTED` when
`units` has no `day` or `hour`.
