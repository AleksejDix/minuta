export const units = createUnits();

Round a date or a moment to a neat boundary: the nearest quarter hour, the
next midnight, the start of the week.

```ts
import { snapWith } from "@aleksejdix/minuta/intervals";
```

```ts
snapWith(units, value, unit, options?)
```

## Example

```ts
import { snapWith } from "@aleksejdix/minuta/intervals";
import { createUnits } from "@aleksejdix/minuta/core";

const units = createUnits();
const date = Temporal.ZonedDateTime.from("2026-03-15T10:37[Europe/Zurich]"); // Sun Mar 15, 10:37

snapWith(units, date, "minute", { step: 15 }); // → 10:30
snapWith(units, date, "minute", { step: 15, mode: "ceil" }); // → 10:45
snapWith(units, date, "day", { mode: "ceil" }); // → 2026-03-16T00:00
snapWith(units, Temporal.PlainDate.from("2026-03-18"), "week", {
  mode: "floor",
}); // → 2026-03-16
```

## Parameters

| Name      | What it is                                                                   |
| --------- | ---------------------------------------------------------------------------- |
| `units`   | The units to compute with, e.g. `createUnits()`. They decide the week start. |
| `value`   | The date (`PlainDate`) or moment (`ZonedDateTime`) to round.                 |
| `unit`    | Whose boundaries to round to: `"minute"`, `"hour"`, `"day"`, `"week"`, …     |
| `options` | Optional. `step` and `mode`, see [Options](#options) below.                  |

## Options

| Option | Default     | What it does                                                                                                       |
| ------ | ----------- | ------------------------------------------------------------------------------------------------------------------ |
| `mode` | `"nearest"` | `"floor"` goes back to the boundary before, `"ceil"` forward to the boundary after, `"nearest"` to the closer one. |
| `step` | `1`         | How many units lie between boundaries. `{ step: 15 }` with `"minute"` gives :00, :15, :30, :45.                    |

## Returns

A boundary of the same kind as `value`. A date snaps to dates, so only to
date units (`"day"` and larger). A moment snaps to moments in its own zone;
for date units, to the start of a day. When `value` already is a boundary,
you get it back, whatever the mode.

## Nearest, and ties

`"nearest"` picks the closer boundary. Exactly in the middle, it rounds up:

```ts
snapWith(
  units,
  Temporal.ZonedDateTime.from("2026-03-15T10:30[Europe/Zurich]"),
  "hour"
); // → 11:00
snapWith(
  units,
  Temporal.ZonedDateTime.from("2026-03-15T12:00[Europe/Zurich]"),
  "day"
); // → 2026-03-16T00:00
snapWith(
  units,
  Temporal.ZonedDateTime.from("2026-03-15T10:37:30[Europe/Zurich]"),
  "minute"
); // → 10:38
```

## Where steps are counted from

Steps start again in every larger unit, so they follow the clock and the
calendar:

| Unit               | Steps counted from      |
| ------------------ | ----------------------- |
| `second`           | the start of the minute |
| `minute`           | the start of the hour   |
| `hour`             | the start of the day    |
| `day`              | the start of the month  |
| `month`, `quarter` | the start of the year   |
| `week`, `year`     | 1970                    |

```ts
snapWith(
  units,
  Temporal.ZonedDateTime.from("2026-03-15T10:37[Europe/Zurich]"),
  "hour",
  {
    step: 6,
    mode: "floor",
  }
);
// → 06:00 (boundaries at 0:00, 6:00, 12:00, 18:00)

snapWith(units, Temporal.PlainDate.from("2026-05-20"), "month", {
  step: 3,
  mode: "floor",
});
// → 2026-04-01 (boundaries at Jan, Apr, Jul, Oct)

snapWith(units, Temporal.PlainDate.from("2026-05-20"), "year", {
  step: 10,
  mode: "floor",
});
// → 2020-01-01 (decades)

snapWith(units, Temporal.PlainDate.from("2026-03-18"), "week", {
  step: 2,
  mode: "floor",
});
// → 2026-03-09, a Monday (every second week, counted from 1970)
```

## The last step is cut short

When a step does not divide the larger unit evenly, the last step ends where
the larger unit ends. Days in steps of 7 from the start of March are Mar 1,
8, 15, 22 and 29. The next one would be Apr 5, but April 1 comes first:

```ts
snapWith(units, Temporal.PlainDate.from("2026-03-30"), "day", {
  step: 7,
  mode: "ceil",
});
// → 2026-04-01
```

```ts
snapWith(
  units,
  Temporal.ZonedDateTime.from("2026-03-15T22:37[Europe/Zurich]"),
  "hour",
  {
    step: 5,
    mode: "ceil",
  }
);
// → 2026-03-16T00:00 (not 25:00)
```

## Clock changes

Hours are real hours. On Mar 29 2026 in Europe/Zurich the clock skips 2:00,
so rounding to the hour around it lands on 3:00:

```ts
snapWith(
  units,
  Temporal.ZonedDateTime.from("2026-03-29T01:40[Europe/Zurich]"),
  "hour"
); // → 03:00 summer time
```

Steps of hours count real hours since midnight. On that day 3:00 is only 2
hours after midnight, so with `{ step: 3 }` the boundaries are 0:00, 4:00,
7:00 … instead of 0:00, 3:00, 6:00:

```ts
snapWith(
  units,
  Temporal.ZonedDateTime.from("2026-03-29T05:10[Europe/Zurich]"),
  "hour",
  {
    step: 3,
    mode: "floor",
  }
);
// → 04:00
```

## Week start

Week boundaries follow the week start of the units:

```ts
snapWith(
  createUnits({ weekStartsOn: "sunday" }),
  Temporal.PlainDate.from("2026-03-18"),
  "week",
  { mode: "floor" }
);
// → 2026-03-15, a Sunday
```

## Errors

`snapWith` throws a `RangeError` whose message starts with a code:

| Code                 | When                                                                              |
| -------------------- | --------------------------------------------------------------------------------- |
| `INVALID_OPTION`     | `step` is not a positive whole number (0, 1.5, -1).                               |
| `UNIT_NOT_SUPPORTED` | `units` has no spec for `unit` or for the larger unit the steps are counted from. |

```ts
snapWith(units, date, "minute", { step: 0 });
// RangeError: INVALID_OPTION: snapWith() step must be a positive whole number, got 0. …
```

A date with a time unit throws a `TypeError`: dates have no hours.

```ts
snapWith(units, Temporal.PlainDate.from("2026-03-18"), "hour");
// TypeError: A date snaps to date units, not to "hour": snap a ZonedDateTime instead.
```
