Check whether two periods share any time, for example two bookings that
clash.

```ts
import { overlaps } from "@aleksejdix/minuta";
```

```ts
overlaps(first, second);
```

## Example

```ts
import { overlaps, range } from "@aleksejdix/minuta";

const booking = range(
  Temporal.PlainDate.from("2026-03-01"),
  Temporal.PlainDate.from("2026-03-10")
);
const other = range(
  Temporal.PlainDate.from("2026-03-05"),
  Temporal.PlainDate.from("2026-03-20")
);

overlaps(booking, other);
// → true, both include Mar 5 to Mar 9
```

## Parameters

| Name     | What it is        |
| -------- | ----------------- |
| `first`  | One period.       |
| `second` | The other period. |

## Returns

`true` when some time is in both periods, otherwise `false`.
The order does not matter: `overlaps(a, b)` equals `overlaps(b, a)`.

A period that lies fully inside the other also overlaps it. To ask whether
one period is _completely_ inside another, use [`contains`](../contains/).

## Neighbours do not overlap

A period's `end` is not part of it. Periods from [`period`](../period/),
[`next`](../next/) and [`divide`](../divide/) end exactly where the next one
starts, so neighbors touch but never overlap:

```ts
import { overlaps, period } from "@aleksejdix/minuta";

const march = period(Temporal.PlainDate.from("2026-03-01"), "month");
const april = period(Temporal.PlainDate.from("2026-04-01"), "month");

overlaps(march, april); // → false
```

A period that crosses the border does overlap both sides:

```ts
overlaps(period(Temporal.PlainDate.from("2026-03-31"), "week"), april);
// → true, the week Mon Mar 30 – Sun Apr 5
```

## Touching ranges do not overlap

The same holds for any [`range`](../range/). A range from 9:00 to 10:00 stops
right before 10:00, so it does not clash with a range from 10:00 to 11:00:

```ts
const at = (time) =>
  Temporal.ZonedDateTime.from(`2026-03-02T${time}[Europe/Zurich]`);

overlaps(range(at("09:00"), at("10:00")), range(at("10:00"), at("11:00")));
// → false
```

Back-to-back bookings are free of clashes without any adjustment.

## Dates and moments

`overlaps` can compare a period of dates with a period of moments. The
dates then become moments in the other period's time zone: the day Mar 18
runs from its start to the start of Mar 19.

## The unit does not matter

`overlaps` only compares values. It needs no units.
