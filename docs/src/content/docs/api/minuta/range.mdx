export const trip = range(plainDate("2026-03-18"), plainDate("2026-03-25"));

  period(plainDate("2026-03-25"), "day").end

Make a period between any two dates or moments: a meeting from 9:00 to
10:00, a trip from Jan 1 to Mar 31, a billing cycle.

```ts
import { range } from "@aleksejdix/minuta";
```

```ts
range(start, end);
```

## Example

```ts
import { range } from "@aleksejdix/minuta";

range(
  Temporal.PlainDate.from("2026-01-01"),
  Temporal.PlainDate.from("2026-04-01")
);
// → { start: 2026-01-01, end: 2026-04-01, unit: "custom" }: January to March
```

## Parameters

| Name    | What it is                                                     |
| ------- | -------------------------------------------------------------- |
| `start` | One edge of the period: a `PlainDate` or a `ZonedDateTime`.    |
| `end`   | The other edge, of the same kind: both dates, or both moments. |

## Returns

A period with the unit `"custom"`. `start` and `end` are the values you
passed, unchanged. `start` is part of the period, `end` is not: the end is
_exclusive_.

Two dates make a period of dates, two `ZonedDateTime`s a period of moments.
`"custom"` means "not one whole unit". See
[Periods and units](../../../concepts/periods-and-units/).

## The end is not included

`range` stops right before `end`. A range of dates that ends on Mar 31 does
not include Mar 31 itself:

```ts
import { contains, count, range } from "@aleksejdix/minuta";

const q1 = range(
  Temporal.PlainDate.from("2026-01-01"),
  Temporal.PlainDate.from("2026-03-31")
);

contains(q1, Temporal.PlainDate.from("2026-03-31")); // → false
count(q1, "day"); // → 89
```

To include the whole last day, end the range at the day after it. The `end`
of a day [`period`](../period/) is exactly that:

```ts
import { count, period, range } from "@aleksejdix/minuta";

const q1 = range(
  Temporal.PlainDate.from("2026-01-01"),
  period(Temporal.PlainDate.from("2026-03-31"), "day").end
);
// → { start: 2026-01-01, end: 2026-04-01, unit: "custom" }

count(q1, "day"); // → 90
```

Ranges are hatched because their unit is `"custom"`. The first one stops
where the last day begins; the second one ends with it.

:::tip
Because the end is excluded, back-to-back slots share a boundary: a range
from 9:00 to 10:00 is exactly one hour, and it only touches a range that
starts at 10:00. [`overlaps`](../overlaps/) says `false` for the two.
:::

## Values in the wrong order are swapped

`range` is forgiving. If `start` is later than `end`, it swaps them:

```ts
range(
  Temporal.PlainDate.from("2026-04-01"),
  Temporal.PlainDate.from("2026-01-01")
);
// → { start: 2026-01-01, end: 2026-04-01, unit: "custom" }
```

A range may also start and end at the same value. It is then empty.

## Errors

`range` throws a `TypeError` when `start` and `end` are of different kinds,
a `PlainDate` and a `ZonedDateTime`. Convert one first, e.g. with
`date.toZonedDateTime(timeZone)` or `moment.toPlainDate()`.
