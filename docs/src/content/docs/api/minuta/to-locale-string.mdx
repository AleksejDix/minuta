  units.map((unit) => ({

    periods: [time[unit](date)],
    tone: "accent",
  }));

  period(plainDate("2026-03-01"), plainDate("2026-04-01")),
  period(plainDate("2026-03-30"), plainDate("2026-04-06")),
  period(plainDate("2025-12-29"), plainDate("2026-01-05")),
];
export const q2 = quarter(plainDate("2026-05-01"));

Turn a period into text for people to read, in any language: "March 2026",
"15. März 2026", "Mar 9 – 15, 2026". Like Temporal's `toLocaleString()`,
with a format picked by the period's unit.

```ts
import { toLocaleString } from "@aleksejdix/minuta";
```

```ts
toLocaleString(period, locales?, options?)
```

## Example

```ts
import { day, month, toLocaleString, week } from "@aleksejdix/minuta";

const date = Temporal.ZonedDateTime.from("2026-03-15T14:05:09[Europe/Zurich]");

toLocaleString(month(date), "en-US"); // → "March 2026"
toLocaleString(month(date), "de-CH"); // → "März 2026"
toLocaleString(day(date), "en-US"); // → "March 15, 2026"
toLocaleString(week(date), "en-US"); // → "Mar 9 – 15, 2026"
```

## Parameters

| Name      | What it is                                                                                                |
| --------- | --------------------------------------------------------------------------------------------------------- |
| `period`  | The period to show.                                                                                       |
| `locales` | Optional. A BCP 47 tag or a list of them: `"en-US"`, `"de-CH"`, `"ja-JP"`, … The runtime's when left out. |
| `options` | Optional. `Intl.DateTimeFormat` options that replace or add to the defaults, see [Options](#options).     |

## Returns

The text, a string. It is made by the browser's or Node's built-in
`Intl.DateTimeFormat`, so minuta ships no language data. The text is the
same with native Temporal and the polyfill, on a server and in the browser.

## One format per unit

The unit of the period decides what the text shows. For Sun Mar 15 2026,
14:05:09:

| Unit      | `"en-US"`          | `"de-CH"`          | `"ja-JP"`              |
| --------- | ------------------ | ------------------ | ---------------------- |
| `year`    | 2026               | 2026               | 2026年                 |
| `quarter` | Jan 2026           | Jan. 2026          | 2026年1月              |
| `month`   | March 2026         | März 2026          | 2026年3月              |
| `week`    | Mar 9 – 15, 2026   | 9.–15. März 2026   | 2026/03/09～2026/03/15 |
| `day`     | March 15, 2026     | 15. März 2026      | 2026年3月15日          |
| `hour`    | Mar 15, 2:00 PM    | 15. März, 14:00    | 3月15日 14:00          |
| `minute`  | Mar 15, 2:05 PM    | 15. März, 14:05    | 3月15日 14:05          |
| `second`  | Mar 15, 2:05:09 PM | 15. März, 14:05:09 | 3月15日 14:05:09       |

## Ranges

Weeks and `"custom"` periods are shown as a range from start to end. Parts
that start and end share, such as the month or the year, are written only
once (`Intl.DateTimeFormat#formatRange`):

```ts
import { period, toLocaleString } from "@aleksejdix/minuta";

const date = (iso) => Temporal.PlainDate.from(iso);

toLocaleString(period(date("2026-03-01"), date("2026-04-01")), "de-CH");
// → "1.–31. März 2026"

toLocaleString(period(date("2026-03-30"), date("2026-04-06")), "de-CH");
// → "30. März – 5. Apr. 2026"

toLocaleString(period(date("2025-12-29"), date("2026-01-05")), "de-CH");
// → "29. Dez. 2025 – 4. Jan. 2026"
```

A period of dates shows its last day, the day before its excluded `end`. A
period of moments shows its start and its end, where 10:00–11:00 reads
right.

A custom period of dates shows day, short month and year. A custom period of
moments shows its times:

```ts
const workday = period(
  Temporal.ZonedDateTime.from("2026-03-15T09:00[Europe/Zurich]"),
  Temporal.ZonedDateTime.from("2026-03-15T17:00[Europe/Zurich]")
);

toLocaleString(workday, "en-US");
// → "Mar 15, 9:00 AM – 5:00 PM"

toLocaleString(workday, "en-US", { hour: "numeric", minute: "2-digit" });
// → "9:00 AM – 5:00 PM"
```

When start and end look the same in the shown fields, there is no dash at
all: `toLocaleString(period(date("2026-03-15"), date("2026-03-16")), "en-US")`
is "Mar 15, 2026".

## A month or a quarter as a range

A month, a quarter or a year shows its start. A quarter is named by the
month it starts in, which may not be what you want: Q2 2026 becomes
"Apr 2026". To show any period as a range, format a custom period with the same
start and end:

```ts
import { period, quarter, toLocaleString } from "@aleksejdix/minuta";

const q2 = quarter(Temporal.PlainDate.from("2026-05-01"));

toLocaleString(q2, "en-US"); // → "Apr 2026"
toLocaleString(period(q2.start, q2.end), "en-US"); // → "Apr 1 – Jun 30, 2026"
toLocaleString(period(q2.start, q2.end), "en-US", {
  month: "short",
  year: "numeric",
}); // → "Apr – Jun 2026"
```

## Options

`options` are the options of
[`Intl.DateTimeFormat`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat/DateTimeFormat#options).
Options that pick fields (`year`, `month`, `day`, `weekday`, `hour`,
`dateStyle`, `timeStyle` …) replace the defaults of the period's unit: list
every field you want. Other options, such as `hourCycle` or `timeZone`, are
added to the defaults.

```ts
toLocaleString(month(date), "en-US", { month: "short" });
// → "Mar"

toLocaleString(day(date), "en-US", { weekday: "long" });
// → "Sunday"

toLocaleString(day(date), "en-US", { dateStyle: "full" });
// → "Sunday, March 15, 2026"
```

## Time zones

A period of moments is written in its own time zone, the zone of its
`ZonedDateTime`s, wherever the code runs. A period of dates has no zone: it
shows the same day everywhere.

```ts
const tokyo = Temporal.ZonedDateTime.from("2026-03-21T05:00[Asia/Tokyo]");

toLocaleString(day(tokyo), "en-US"); // → "March 21, 2026"
toLocaleString(hour(tokyo), "en-US"); // → "Mar 21, 5:00 AM"
```

To show moments in another zone, pass `timeZone`. It has no effect on a
period of dates.

```ts
toLocaleString(hour(tokyo), "en-US", { timeZone: "Europe/Zurich" });
// → "Mar 20, 9:00 PM"
```

## Other calendars

A period made in another calendar is shown in that calendar: a Hebrew month
reads "Adar I 5784", a Hijri month "Ramadan 1447 AH". See
[calendars](../create-units/#calendars). The `calendar` option picks another
one for the text only.

```ts
import { createUnits, toLocaleString, withUnits } from "@aleksejdix/minuta";

const ramadan = withUnits(createUnits({ calendar: "islamic-umalqura" })).month(
  Temporal.PlainDate.from("2026-03-18")
);
toLocaleString(ramadan, "en-US"); // → "Ramadan 1447 AH"
toLocaleString(ramadan, "en-US", { calendar: "gregory", dateStyle: "long" }); // → "February 18, 2026"
```

For an ISO period, the locale can ask for another calendar system with
`-u-ca-`. Only the text changes; the period is still the same Gregorian
month.

```ts
toLocaleString(month(date), "en-US-u-ca-buddhist"); // → "March 2569 BE"
```

In a locale whose calendar has other month borders, the text is the month
of the period's **start**: for March 2026, `"fa-IR"` gives "۱۴۰۴ اسفند",
the Persian month in which March 1 falls.

## Custom units

A period with a unit minuta has no format for (a unit you added yourself) is
shown like a custom period of dates, but only with its start: "Mar 1, 2026".
Format `period(p.start, p.end)` to show start and end.

## Errors

`toLocaleString` throws the errors of `Intl.DateTimeFormat`:

| Error        | When                                                            |
| ------------ | --------------------------------------------------------------- |
| `RangeError` | A locale is not a valid tag, or an option has an invalid value. |
| `TypeError`  | `options` conflict, e.g. `dateStyle` together with `month`.     |

It does not check the order: a period whose end is before its start is
formatted as it is.
