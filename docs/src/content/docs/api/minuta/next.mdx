Get the period right after a period: the day after a day, the week after a
week, the month after a month.

```ts
import { next } from "@aleksejdix/minuta";
```

```ts
next(period);
```

## Example

```ts
import { next, period } from "@aleksejdix/minuta";

const march = period(Temporal.PlainDate.from("2026-03-15"), "month");

next(march);
// → { start: 2026-04-01, end: 2026-05-01, unit: "month" }
```

## Parameters

| Name     | What it is                                        |
| -------- | ------------------------------------------------- |
| `period` | The current period, e.g. a month from `period()`. |

## Returns

A new period of the same unit that starts where `period` ends:
`next(march).start` equals `march.end`. It is a whole unit, with its own
length: after March (31 days) comes April (30 days).

`next(p)` is the same as [`shift(p, 1)`](../shift/).

## Daylight saving is handled

The next period is found on the calendar, not by adding a fixed amount of
time. A day period holds dates, so a clock change cannot move it. In
Europe/Zurich, Mar 29 2026 has only 23 hours, and it is still the next day:

```ts
next(period(Temporal.PlainDate.from("2026-03-28"), "day"));
// → { start: 2026-03-29, end: 2026-03-30, unit: "day" }
```

The hour after 1:00 on that day is 3:00, because 2:00 does not exist:

```ts
next(
  period(Temporal.ZonedDateTime.from("2026-03-29T01:00[Europe/Zurich]"), "hour")
);
// → { start: 2026-03-29T03:00+02:00, end: 2026-03-29T04:00+02:00, unit: "hour" }
```

## Custom periods move by their own length

A period with the unit `"custom"` (from [`range`](../range/), or a piece cut
by [`divide`](../divide/)) has no unit to step by. `next` moves it forward by
exactly its own length, so the new period starts where the old one ends.

```ts
import { next, range } from "@aleksejdix/minuta";

const slot = range(
  Temporal.ZonedDateTime.from("2026-03-02T09:00[Europe/Zurich]"),
  Temporal.ZonedDateTime.from("2026-03-02T10:00[Europe/Zurich]")
);

next(slot);
// → { start: 2026-03-02T10:00+01:00, end: 2026-03-02T11:00+01:00, unit: "custom" }
```

  tracks={[

    { label: "next(slot)", periods: [next(slot)], tone: "accent" },

A custom period of dates moves by its number of days. A custom period of
moments moves by elapsed time, not on the calendar. A custom week of moments
that ends after a clock change ends an hour off:

```ts
const week = range(
  Temporal.ZonedDateTime.from("2026-03-23T00:00[Europe/Zurich]"),
  Temporal.ZonedDateTime.from("2026-03-30T00:00[Europe/Zurich]")
);

next(week);
// → { start: 2026-03-30T00:00+02:00, end: 2026-04-05T23:00+02:00, unit: "custom" }
```

The same week made of dates, `range(2026-03-23, 2026-03-30)`, moves to
Mar 30 – Apr 6, exactly seven days.

The first and last pieces of a [`divide`](../divide/) are often custom too.
`next` of the clipped two-day week Mon Mar 30 – Tue Mar 31 gives Wed Apr 1 –
Thu Apr 2, not the next week. To step by whole units, use a period from
[`period`](../period/).

## Errors

`next` throws a `RangeError` whose message starts with a code:

| Code                 | When                               |
| -------------------- | ---------------------------------- |
| `UNIT_NOT_SUPPORTED` | `period.unit` is not a known unit. |
