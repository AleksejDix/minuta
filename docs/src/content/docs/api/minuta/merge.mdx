Join several periods into one that runs from the earliest start to the
latest end. When the result is exactly one whole unit, such as one month, it
gets that unit.

```ts
import { merge } from "@aleksejdix/minuta";
```

```ts
merge(periods, unit?)
```

## Example

```ts
import { divide, merge, month } from "@aleksejdix/minuta";

const days = divide(month(Temporal.PlainDate.from("2026-03-01")), "day"); // the 31 days of March

merge(days, "month");
// → { start: 2026-03-01, end: 2026-04-01, unit: "month" }

merge(days);
// → the same start and end, unit "custom"
```

## Parameters

| Name      | What it is                                                                                                                      |
| --------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `periods` | The periods to join, in any order: all dates or all moments.                                                                    |
| `unit`    | Optional. The unit the result should get if it fits exactly, e.g. `"month"`. Without it, the unit of the first period is tried. |

## Returns

One period from the earliest start to the latest end of all `periods`.

- Its unit is `unit` (or the first period's unit) when the result is
  exactly one whole period of that unit.
- Otherwise its unit is `"custom"`.

`undefined` for an empty list.

## Gaps are filled

`merge` does not check whether the periods touch. It always spans from
the first start to the last end, so anything in between is included:

```ts
merge([
  month(Temporal.PlainDate.from("2026-01-01")),
  month(Temporal.PlainDate.from("2026-03-01")),
]);
// → { start: 2026-01-01, end: 2026-04-01, unit: "custom" } (February is included)
```

The same goes for overlapping periods: they become one period with no
double counting.

```ts
import { merge, period } from "@aleksejdix/minuta";

merge([
  period(
    Temporal.ZonedDateTime.from("2026-01-01T09:00[Europe/Zurich]"),
    Temporal.ZonedDateTime.from("2026-01-01T11:00[Europe/Zurich]")
  ),
  period(
    Temporal.ZonedDateTime.from("2026-01-01T10:00[Europe/Zurich]"),
    Temporal.ZonedDateTime.from("2026-01-01T12:00[Europe/Zurich]")
  ),
]);
// → 09:00 – 12:00, unit "custom"
```

[`overlaps`](../overlaps/) to group them first, then merge each
group.

## When the unit is kept

The unit is checked, not guessed from the input:

```ts
const jan = month(Temporal.PlainDate.from("2026-01-01"));
const feb = month(Temporal.PlainDate.from("2026-02-01"));
const mar = month(Temporal.PlainDate.from("2026-03-01"));
const mar3 = day(Temporal.PlainDate.from("2026-03-03"));

merge([jan, feb]); // → 2026-01-01 – 2026-03-01, "custom" (two months are not a month)
merge([jan, feb], "quarter"); // → "custom" (only part of a quarter)
merge([jan, feb, mar], "quarter"); // → 2026-01-01 – 2026-04-01, "quarter"

merge([mar3]); // → 2026-03-03 – 2026-03-04, "day"
merge([mar3], "week"); // → 2026-03-03 – 2026-03-04, "custom"
```

Two halves of a custom split come back as the month:

```ts
const firstHalf = period(
  Temporal.PlainDate.from("2026-01-01"),
  Temporal.PlainDate.from("2026-01-16")
);
const secondHalf = period(
  Temporal.PlainDate.from("2026-01-16"),
  Temporal.PlainDate.from("2026-02-01")
);

merge([firstHalf, secondHalf], "month"); // → January, unit "month"
merge([firstHalf, secondHalf]); // → January, unit "custom" (the first is "custom")
```

## Week start

Whether seven days are "a week" depends on the week start: Monday here. For
another week start, take `merge` from [`withUnits`](../with-units/). Mon
Mar 16 to Sun Mar 22 2026:

```ts
const days7 = divide(
  period(
    Temporal.PlainDate.from("2026-03-16"),
    Temporal.PlainDate.from("2026-03-23")
  ),
  "day"
);

merge(days7, "week"); // → unit "week"
withUnits(createUnits({ weekStartsOn: "sunday" })).merge(days7, "week"); // → unit "custom"
```

## Errors

`merge` throws a `RangeError` starting with `UNIT_NOT_SUPPORTED` when the
units have no spec for the unit it has to check, and a `TypeError` when
`periods` mixes dates and moments.
