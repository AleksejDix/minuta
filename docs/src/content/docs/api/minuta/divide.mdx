Split a period into smaller periods: a month into days, a day into hours, an
hour into 15-minute slots.

```ts
import { divide } from "@aleksejdix/minuta";
```

```ts
divide(period, unit, options?)
```

## Example

```ts
import { divide, period } from "@aleksejdix/minuta";

const march = period(Temporal.PlainDate.from("2026-03-01"), "month");

divide(march, "day");
// → 31 periods: Mar 1, Mar 2, … Mar 31
```

## Parameters

| Name      | What it is                                                        |
| --------- | ----------------------------------------------------------------- |
| `period`  | The period to split, e.g. a month from `period()`.                |
| `unit`    | The size of each piece: `"day"`, `"hour"`, `"week"`, …            |
| `options` | Optional. `step` and `maxPeriods`, see [Options](#options) below. |

## Returns

An array of periods, in order, that together cover `period` exactly — no gaps,
no overlaps. Each piece ends exactly where the next one starts.

A period of dates divided into a date unit (a month into days) gives periods
of dates. Divided into a time unit (a day into hours), its days become moments
in the units' time zone, the runtime's by default. So a day the clocks change
on has 23 or 25 hours:

```ts
divide(period(Temporal.PlainDate.from("2026-03-29"), "day"), "hour").length;
// → 23 in Europe/Zurich
```

For a fixed zone, use `divideWith` with `createUnits({ timeZone: "UTC" })`,
or divide a range of two `ZonedDateTime`s, which keeps their zone. A day
made from a `ZonedDateTime` is a date, so it uses the units' zone.

## Options

| Option       | Default   | What it does                                                                           |
| ------------ | --------- | -------------------------------------------------------------------------------------- |
| `step`       | `1`       | How many units each piece spans. `{ step: 15 }` with `"minute"` gives 15-minute slots. |
| `maxPeriods` | `100_000` | A safety limit. `divide` throws instead of creating more pieces than this.             |

```ts
const nine = period(
  Temporal.ZonedDateTime.from("2026-03-01T09:00[Europe/Zurich]"),
  "hour"
);

divide(nine, "minute", { step: 15 });
// → 4 periods: 9:00–9:15, 9:15–9:30, 9:30–9:45, 9:45–10:00
```

A piece never sticks out of `period`. When the units don't line up with it,
the first and last pieces are cut at its edges and get the unit `"custom"`,
because they are no longer a whole week or day.

```ts
divide(march, "week");
// → 2026-03-01 – 2026-03-02  "custom"  (the week started in February)
//   2026-03-02 – 2026-03-09  "week"
//   2026-03-09 – 2026-03-16  "week"
//   2026-03-16 – 2026-03-23  "week"
//   2026-03-23 – 2026-03-30  "week"
//   2026-03-30 – 2026-04-01  "custom"  (the week ends in April)
```

Pieces made with a `step` larger than 1 are always `"custom"` too: 15 minutes
is not one whole unit.

Weeks start on Monday here. To start them on Sunday, use `divideWith` from
`@aleksejdix/minuta/core` with `createUnits({ weekStartsOn: "sunday" })`.

## Errors

`divide` throws a `RangeError` whose message starts with a code:

| Code               | When                                                            |
| ------------------ | --------------------------------------------------------------- |
| `TOO_MANY_PERIODS` | More than `maxPeriods` pieces — e.g. a year split into seconds. |
| `INVALID_OPTION`   | `step` or `maxPeriods` is not a positive whole number.          |

```ts
divide(period(Temporal.PlainDate.from("2026-01-01"), "year"), "second");
// RangeError: TOO_MANY_PERIODS: divideWith() generated over 100000 periods. …
```
