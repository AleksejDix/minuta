title: createUnits
description: The units minuta computes with — the rules for each unit of time, the week start, the weekend and the time zone.
---

import { plainDate } from "../../../../components/temporal";
import { createUnits, withUnits } from "@aleksejdix/minuta";
import Timeline from "../../../../components/diagrams/Timeline.astro";

export const hijri = createUnits({ calendar: "islamic-umalqura" });
export const earlyMonths = (units) =>
  withUnits(units).divide(
    {
      end: plainDate("2026-05-01"),
      start: plainDate("2026-01-01"),
      unit: "custom",
    },
    "month"
  );
export const isoMonths = earlyMonths(createUnits());
export const hijriMonths = earlyMonths(hijri);

export const weeksOfMarch = (units) => {
  const time = withUnits(units);
  return time.divide(time.period(plainDate("2026-03-01"), "month"), "week");
};

Makes the **units**: one rule set per unit of time (`year`, `quarter`,
`month`, `week`, `day`, `hour`, `minute`, `second`), computed with
[Temporal](https://tc39.es/proposal-temporal/docs/), plus the week start, the
weekend, the time zone and the calendar. Pass them to
[`withUnits`](../with-units/) to get every function bound to them.

```ts
import { createUnits } from "@aleksejdix/minuta";
```

```ts
createUnits(options?)
```

The functions of `@aleksejdix/minuta` are bound to `createUnits()`: weeks
start on Monday, the time zone is the runtime's. Call it yourself for
anything else.

## Example

```ts
import { createUnits, withUnits } from "@aleksejdix/minuta";

const time = withUnits(createUnits({ weekStartsOn: "sunday" }));

time.period(Temporal.PlainDate.from("2026-03-18"), "week");
// → { start: 2026-03-15, end: 2026-03-22, unit: "week" }
```

The weeks of March 2026, starting on Monday and on Sunday. The hatched
pieces are cut at the month's edges:

## Parameters

| Name      | What it is                                                                              |
| --------- | --------------------------------------------------------------------------------------- |
| `options` | Optional. Week start, weekend, locale, time zone and calendar, see [Options](#options). |

## Options

| Option         | Default                  | What it does                                                                                                                                                                                        |
| -------------- | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `weekStartsOn` | `"monday"`               | The first day of the week: `"sunday"` … `"saturday"`, or 0 (Sunday) … 6 (Saturday).                                                                                                                 |
| `weekend`      | `["saturday", "sunday"]` | The days that [`isWeekend`](../is-weekend/) counts as weekend.                                                                                                                                      |
| `locale`       | none                     | Takes `weekStartsOn` and `weekend` from a locale's week (`Intl.Locale#getWeekInfo`): `"en-US"` starts on Sunday, `"ar-EG"` on Saturday with a Friday–Saturday weekend. The two options win over it. |
| `timeZone`     | the runtime's zone       | The IANA zone dates become moments in, e.g. when a day is divided into hours: `"UTC"`, `"Europe/Zurich"`.                                                                                           |
| `calendar`     | each date's own          | The [calendar](#calendars) every date is read in, e.g. `"hebrew"`, `"islamic-umalqura"`, `"persian"`.                                                                                               |

Hours, minutes and seconds made from a `ZonedDateTime` keep its zone; a day
or longer is made of dates, which have none. `timeZone` applies where a date
has to become a moment, as when a day is divided into hours.

## Returns

The units: a spec for each unit, plus `timeZone`, `weekStartsOn` (a number,
0 = Sunday) and `weekend` (numbers). Add your own units by spreading them:
`{ ...createUnits(), fortnight }`.

## Calendars

Months and years follow the calendar of the date they are made from:
Temporal carries it in every date. A Hebrew date gives a Hebrew month, a
Hijri date a lunar month of 29 or 30 days. With `calendar`, every date is
read in that calendar first, so ISO dates give Hijri months too:

```ts
const hijri = withUnits(createUnits({ calendar: "islamic-umalqura" }));

const ramadan = hijri.period(Temporal.PlainDate.from("2026-03-18"), "month");
// → { start: 2026-02-18[u-ca=islamic-umalqura], end: 2026-03-20[…], unit: "month" }
hijri.count(ramadan, "day"); // → 30
```

Every calendar Temporal has works: `buddhist`, `chinese`, `coptic`, `dangi`,
`ethioaa`, `ethiopic`, `gregory`, `hebrew`, `indian`, `islamic-civil`,
`islamic-tbla`, `islamic-umalqura`, `iso8601`, `japanese`, `persian`, `roc`.
The polyfill `temporalReady()` loads (`temporal-polyfill`'s full build)
computes them all too; its Chinese and Dangi dates come from the runtime's
`Intl` data, so they can differ from native Temporal by a day around the
start of a month.

- **Years with 13 months.** A Hebrew leap year has 13 months, an Ethiopic
  year always does. There are still four quarters: a leap month (Adar I)
  joins the quarter of the month it repeats, a 13th month (Pagume) joins the
  fourth quarter. See [quarters in years with 13 months](../../../concepts/calendar-systems/#quarters-in-years-with-13-months).
- **Japanese eras.** A `year` is the whole year, even when an era starts in
  it: 2019 runs from Heisei 31 into Reiwa 1.
- **Labels** follow the period's calendar, and every calendar is shown side
  by side in [Calendar systems](../../../concepts/calendar-systems/); see
  [`toLocaleString`](../to-locale-string/#other-calendars).

## Temporal

minuta reads `globalThis.Temporal` when it computes, never at import. Where
the runtime has none (Safari, Node 24), `await temporalReady()` once before
anything renders; see [`temporalReady`](../../minuta-temporal/temporal-ready/).
