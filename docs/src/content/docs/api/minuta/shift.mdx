Move a period forward or back by a number of its own unit: three months
ahead, two weeks back, one year back.

```ts
import { shift } from "@aleksejdix/minuta";
```

```ts
shift(period, steps);
```

## Example

```ts
import { period, shift } from "@aleksejdix/minuta";

const march = period(Temporal.PlainDate.from("2026-03-15"), "month");

shift(march, 3);
// → { start: 2026-06-01, end: 2026-07-01, unit: "month" }

shift(march, -14);
// → { start: 2025-01-01, end: 2025-02-01, unit: "month" }
```

## Parameters

| Name     | What it is                                                                          |
| -------- | ----------------------------------------------------------------------------------- |
| `period` | The period to move, e.g. a month from `period()`.                                   |
| `steps`  | How many periods to move, as a whole number. Positive moves forward, negative back. |

## Returns

A new, whole period of the same unit, `steps` periods away. It has its own
length: three months after March is June, with 30 days.

With `steps` of `0`, `shift` returns the very same `period` object.

[`next`](../next/) is `shift(period, 1)`, [`previous`](../previous/) is
`shift(period, -1)`.

## The unit is the period's own

`shift` has no unit argument. It always steps by the unit stored in
`period.unit`. A week moves by weeks, a day by days:

```ts
shift(period(Temporal.PlainDate.from("2026-03-18"), "week"), -1);
// → { start: 2026-03-09, end: 2026-03-16, unit: "week" }
```

To move a day period by months, first get the month with
[`period`](../period/): `shift(period(day.start, "month"), 2)`.

## Custom periods move by their own length

A period with the unit `"custom"` (from [`range`](../range/), or a piece cut
by [`divide`](../divide/)) moves by `steps` times its own length: days for a
period of dates, elapsed time for a period of moments.

```ts
import { range, shift } from "@aleksejdix/minuta";

const slot = range(
  Temporal.ZonedDateTime.from("2026-03-02T09:00[Europe/Zurich]"),
  Temporal.ZonedDateTime.from("2026-03-02T10:00[Europe/Zurich]")
);

shift(slot, 2);
// → { start: 2026-03-02T11:00+01:00, end: 2026-03-02T12:00+01:00, unit: "custom" }
```

For moments this is elapsed time, not calendar time: across a
daylight-saving change, a custom period ends up an hour off the clock. See
[`next`](../next/#custom-periods-move-by-their-own-length) for an example.

:::caution
Pass whole numbers. `steps` is not checked: a fraction throws for some units
and is rounded for others, so do not rely on it.
:::

## Errors

`shift` throws a `RangeError` whose message starts with a code:

| Code                 | When                               |
| -------------------- | ---------------------------------- |
| `UNIT_NOT_SUPPORTED` | `period.unit` is not a known unit. |

With `steps` of `0` nothing is checked: the period comes back as it is.
