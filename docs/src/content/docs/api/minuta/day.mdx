Get the whole day that a date or a moment falls in.

```ts
import { day } from "@aleksejdix/minuta";
```

```ts
day(value);
```

## Example

```ts
import { day } from "@aleksejdix/minuta";

day(Temporal.PlainDate.from("2026-03-18"));
// → { start: 2026-03-18, end: 2026-03-19, unit: "day" }
```

## Parameters

| Name    | What it is                                                  |
| ------- | ----------------------------------------------------------- |
| `value` | A `PlainDate` or a `ZonedDateTime` anywhere inside the day. |

## Returns

A `DatePeriod` with the unit `"day"`: `start` is the date, `end` the next
date. The end is excluded. A day holds dates with no time of day, so a clock
change cannot move it: Mar 29 2026, when the clocks jump from 2:00 to 3:00
in Europe/Zurich, is still one date.

## A moment's day is its date, in its own zone

A `ZonedDateTime` keeps its zone, and its day is the date it shows there:

```ts
day(Temporal.ZonedDateTime.from("2026-03-18T23:30[Asia/Tokyo]"));
// → { start: 2026-03-18, end: 2026-03-19, unit: "day" }
```

`day` takes no `Instant`, so it never guesses a zone. Give the instant one
first. The zone decides the day:

```ts
const instant = Temporal.Instant.from("2026-03-18T23:35:00Z");

day(instant.toZonedDateTimeISO("Europe/Zurich"));
// → { start: 2026-03-19, end: 2026-03-20, unit: "day" }
day(instant.toZonedDateTimeISO("America/New_York"));
// → { start: 2026-03-18, end: 2026-03-19, unit: "day" }
```

See [Time zones](../../../concepts/time-zones/).

## Errors

The main entry's `day` does not throw for a date or a moment. From
[`withUnits`](../with-units/), units without a `day` spec give
`UNIT_NOT_SUPPORTED`.
