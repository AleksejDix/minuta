Count how many whole units fit into a period: the hours in a day, the days in
a month, the weeks in a year.

```ts
import { count } from "@aleksejdix/minuta";
```

```ts
count(period, unit);
```

## Example

```ts
import { count, day, month } from "@aleksejdix/minuta";

count(month(Temporal.PlainDate.from("2026-02-01")), "day");
// → 28

count(day(Temporal.PlainDate.from("2026-10-08")), "hour");
// → 24
```

## Parameters

| Name     | What it is                                               |
| -------- | -------------------------------------------------------- |
| `period` | The period to measure, e.g. a month from `month()`.      |
| `unit`   | What to count: `"day"`, `"hour"`, `"week"`, `"month"`, … |

## Returns

A whole number: how many complete `unit`s fit from the start of `period` to
its end. Units that only partly fit are not counted.

```ts
import { count, month, period } from "@aleksejdix/minuta";

const march = month(Temporal.PlainDate.from("2026-03-01"));

count(march, "week"); // → 4  (31 days)
count(march, "year"); // → 0

const meeting = period(
  Temporal.ZonedDateTime.from("2026-03-01T09:00[Europe/Zurich]"),
  Temporal.ZonedDateTime.from("2026-03-01T10:30[Europe/Zurich]")
);
count(meeting, "hour"); // → 1
```

`count` only counts. To get the pieces themselves, use
[`divide`](../divide/).

## Calendar units, not fixed lengths

Units are counted on the calendar, so a day is not always 24 hours and a year
is not always 365 days. A day counted in hours becomes moments in the units'
time zone first (the runtime's by default). In Europe/Zurich:

```ts
count(day(Temporal.PlainDate.from("2026-03-29")), "hour"); // → 23 (clocks go forward)
count(day(Temporal.PlainDate.from("2026-10-25")), "hour"); // → 25 (clocks go back)
count(year(Temporal.PlainDate.from("2028-01-01")), "day"); // → 366 (leap year)
```

`count` gives a number. For the elapsed time as a `Temporal.Duration`, use
Temporal: `period.start.until(period.end)`.

## Another time zone

Whether a day has 23, 24 or 25 hours depends on the time zone. A date period
counted in hours becomes moments in the units' `timeZone`. For a fixed zone,
count with the functions of [`withUnits`](../with-units/):

```ts
import { createUnits, day, withUnits } from "@aleksejdix/minuta";

const newYork = withUnits(createUnits({ timeZone: "America/New_York" }));

newYork.count(day(Temporal.PlainDate.from("2026-03-08")), "hour");
// → 23, the clocks go forward in New York on Mar 8 2026
```

## Counting starts at the start

Whole units are counted from `period.start`, not on unit boundaries. A
period from 14:00 one day to 13:00 the next is 23 hours, so it holds zero
whole days:

```ts
count(
  period(
    Temporal.ZonedDateTime.from("2026-03-15T14:00[Europe/Zurich]"),
    Temporal.ZonedDateTime.from("2026-03-16T13:00[Europe/Zurich]")
  ),
  "day"
);
// → 0
```

Month steps follow the calendar too. One month after Jan 31 is Feb 28 (the
day is cut to the shorter month), so this period already holds one month:

```ts
count(
  period(
    Temporal.PlainDate.from("2026-01-31"),
    Temporal.PlainDate.from("2026-02-28")
  ),
  "month"
);
// → 1
```

## The end is excluded

The period's `end` is where it stops, so `count` measures up to `end`
itself. A whole day counts as one day. A [`period`](../period/) that ends on
Mar 31 stops where Mar 31 begins:

```ts
const jan1 = Temporal.PlainDate.from("2026-01-01");

count(period(jan1, Temporal.PlainDate.from("2026-03-31")), "day");
// → 89, Mar 31 itself is not included

count(period(jan1, Temporal.PlainDate.from("2026-04-01")), "day");
// → 90
```

## Errors

`count` throws a `RangeError` whose message starts with a code:

| Code                 | When                                            |
| -------------------- | ----------------------------------------------- |
| `UNIT_NOT_SUPPORTED` | `unit` is not a known unit, e.g. `"fortnight"`. |
