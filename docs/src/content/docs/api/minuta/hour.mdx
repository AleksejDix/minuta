Get the whole hour that a moment falls in.

```ts
import { hour } from "@aleksejdix/minuta";
```

```ts
hour(value);
```

## Example

```ts
import { hour } from "@aleksejdix/minuta";

hour(Temporal.ZonedDateTime.from("2026-03-18T10:30[Europe/Zurich]"));
// → { start: 2026-03-18T10:00+01:00[Europe/Zurich], end: 2026-03-18T11:00+01:00[…], unit: "hour" }
```

## Parameters

| Name    | What it is                                                              |
| ------- | ----------------------------------------------------------------------- |
| `value` | A `ZonedDateTime` inside the hour, or a `PlainDate` for its first hour. |

## Returns

A `TimePeriod` with the unit `"hour"`: `start` and `end` are
`ZonedDateTime`s, one elapsed hour apart. The end is excluded, so 10:00 to
11:00 does not overlap 11:00 to 12:00.

## A date becomes its first hour

A `ZonedDateTime` keeps its own zone. A `PlainDate` has none, so it starts
at the beginning of its day in the units' time zone: the runtime's for the
main entry, or the `timeZone` you give the units:

```ts
import { createUnits, withUnits } from "@aleksejdix/minuta";

const tokyo = withUnits(createUnits({ timeZone: "Asia/Tokyo" }));

tokyo.hour(Temporal.PlainDate.from("2026-03-18"));
// → { start: 2026-03-18T00:00+09:00[Asia/Tokyo], end: 2026-03-18T01:00+09:00[…], unit: "hour" }
```

## Clock changes: 23 and 25 hours

Hours are real elapsed hours. When the clocks change, a day has 23 or 25 of
them. In Europe/Zurich the clocks jump from 2:00 to 3:00 on Mar 29 2026, so
the hour after 1:00 is 3:00:

```ts
import { createUnits, day, hour, next, withUnits } from "@aleksejdix/minuta";

const zurich = withUnits(createUnits({ timeZone: "Europe/Zurich" }));

next(hour(Temporal.ZonedDateTime.from("2026-03-29T01:30[Europe/Zurich]")));
// → { start: 2026-03-29T03:00+02:00[Europe/Zurich], end: 2026-03-29T04:00+02:00[…], unit: "hour" }

zurich.count(day(Temporal.PlainDate.from("2026-03-29")), "hour"); // → 23
zurich.count(day(Temporal.PlainDate.from("2026-10-25")), "hour"); // → 25
```

On Oct 25 the clocks go back from 3:00 to 2:00, and the hour from 2:00 comes
twice: once at `+02:00`, once at `+01:00`.

## Errors

The main entry's `hour` does not throw for a date or a moment. From
[`withUnits`](../with-units/), units without an `hour` spec give
`UNIT_NOT_SUPPORTED`.
