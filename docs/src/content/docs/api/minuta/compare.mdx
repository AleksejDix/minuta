Order two periods: by their start, and when the starts are equal, by their
end. Like Temporal's `compare()`, it is a callback for `sort`.

```ts
import { compare } from "@aleksejdix/minuta";
```

```ts
compare(first, second);
```

## Example

```ts
import { compare, month, next } from "@aleksejdix/minuta";

const march = month(Temporal.PlainDate.from("2026-03-15"));
const april = next(march);

[april, march].sort(compare); // → [march, april]
compare(march, april); // → -1
compare(april, march); // → 1
compare(march, march); // → 0
```

Four periods sorted with `compare`, the first on top. The day and the week
both start on Mon Mar 16; the day ends first, so it comes first:

## Parameters

| Name     | What it is        |
| -------- | ----------------- |
| `first`  | One period.       |
| `second` | The other period. |

## Returns

A negative number when `first` comes first, a positive number when
`second` does, and `0` when both have the same start and the same end.

```ts
const monday = day(Temporal.PlainDate.from("2026-03-16"));
const thisWeek = week(Temporal.PlainDate.from("2026-03-16"));

compare(monday, thisWeek); // → -1: the same start, the day ends first
```

## Only the times count

`compare` looks at where the periods start and end, not at their units,
calendars or zones. A month and a custom period over the same days compare as `0`,
and so do two hours at the same instant in different zones. To check that
two periods are identical, use [`equals`](../equals/).

## Dates next to moments

A date period and a time period can be compared. The dates become moments
in the zone of the time period: a day starts at its midnight there.

```ts
const monday16 = day(Temporal.PlainDate.from("2026-03-16"));
const firstHour = hour(
  Temporal.ZonedDateTime.from("2026-03-16T00:00[Europe/Zurich]")
);

compare(monday16, firstHour); // → 1: the same start, the hour ends first
```

## Errors

`compare` does not throw. It needs no units.
