`@aleksejdix/minuta` is the main entry point. It has every function, ready
to use: no setup, no configuration. It computes with Temporal in the
runtime's time zone, and weeks start on Monday (ISO 8601).

```ts
import { divide, next, period } from "@aleksejdix/minuta";

const march = period(Temporal.PlainDate.from("2026-03-15"), "month");
// → { start: 2026-03-01, end: 2026-04-01, unit: "month" }

next(march); // → April 2026
divide(march, "day"); // → 31 day periods
```

## The core idea

Every span of time is a **period**: a plain object with a `start`, an `end`
and a `unit`, like `{ start: 2026-03-01, end: 2026-04-01, unit: "month" }`.
The start is part of the period, the end is not: neighboring periods share
a boundary. Days and larger units hold `Temporal.PlainDate`s; hours, minutes
and seconds hold `Temporal.ZonedDateTime`s.

You make a period with [`period`](../period/) (a whole day, week, month …) or
[`range`](../range/) (any two dates or moments). Then you move it, split it, measure it
or compare it. Every function takes plain data and returns new plain data;
nothing is changed in place.

## Functions

| Family    | Function                                 | What it does                                                     |
| --------- | ---------------------------------------- | ---------------------------------------------------------------- |
| Create    | [`period`](../period/)                   | The whole day, week, month … that a date falls in.               |
|           | [`range`](../range/)                     | A period between any two dates or moments.                       |
| Navigate  | [`next`](../next/)                       | The period right after a period.                                 |
|           | [`previous`](../previous/)               | The period right before a period.                                |
|           | [`shift`](../shift/)                     | Move a period forward or back by a number of its own unit.       |
| Compose   | [`divide`](../divide/)                   | Split a period into smaller periods: a month into days.          |
|           | [`merge`](../merge/)                     | One period from the earliest start to the latest end.            |
|           | [`split`](../split/)                     | Cut a period in two at a date.                                   |
| Edit      | [`clamp`](../clamp/)                     | The part of a period that lies inside some bounds.               |
|           | [`gap`](../gap/)                         | The free time between two dates or periods.                      |
|           | [`move`](../move/)                       | Move a period to a new start, keeping its length.                |
|           | [`resize`](../resize/)                   | Move the start or the end, keeping the other edge.               |
| Compare   | [`contains`](../contains/)               | Is a date, a moment or another period inside a period?           |
|           | [`overlaps`](../overlaps/)               | Do two periods share any time?                                   |
|           | [`same`](../same/)                       | Do two periods fall in the same day, week, month …?              |
|           | [`equals`](../equals/)                   | Are two periods identical, like Temporal's `equals()`?           |
|           | [`compare`](../compare/)                 | Order two periods, like Temporal's `compare()`: a sort callback. |
| Measure   | [`count`](../count/)                     | How many whole units fit into a period: the days in a month.     |
|           | [`round`](../round/)                     | Round a date or moment to a boundary, like Temporal's `round()`. |
| Calendars | [`monthGrid`](../month-grid/)            | The 42 days of a month view.                                     |
|           | [`yearGrid`](../year-grid/)              | The whole weeks that cover a year.                               |
|           | [`dayGrid`](../day-grid/)                | The real hours of a day: 23, 24 or 25.                           |
|           | [`isWeekday`](../is-weekday/)            | Does a period lie on working days only?                          |
|           | [`isWeekend`](../is-weekend/)            | Does a period lie on weekend days only?                          |
| Text      | [`toLocaleString`](../to-locale-string/) | A period as text in any language: "March 2026".                  |
| Units     | [`createUnits`](../create-units/)        | Make the units: week start, weekend, time zone, calendar.        |
|           | [`withUnits`](../with-units/)            | Every function above, bound to your units.                       |
|           | [`specFor`](../spec-for/)                | Look up the rules of one unit in a set of units.                 |
| Errors    | [`MinutaError`](../minuta-error/)        | The codes at the start of every error message.                   |

Where Temporal has a word, minuta uses it: `round` takes Temporal's options
and rounding modes, `equals` and `compare` work like Temporal's,
`toLocaleString` formats. `count` returns a number of units, where
`start.until(end)` gives a `Temporal.Duration`.

## Your week, zone, calendar or locale

The functions are ready to use: weeks start on Monday (ISO 8601), moments
lie in the runtime's time zone, and dates keep their own calendar. For
anything else, make units with [`createUnits`](../create-units/) and bind
every function to them with [`withUnits`](../with-units/). You get the same
names back:

```ts
import { createUnits, withUnits } from "@aleksejdix/minuta";

const time = withUnits(createUnits({ weekStartsOn: "sunday" }));

time.period(Temporal.PlainDate.from("2026-03-18"), "week");
// → { start: 2026-03-15, end: 2026-03-22, unit: "week" }
time.monthGrid(Temporal.PlainDate.from("2026-03-18")).periods[0];
// → { start: 2026-03-01, end: 2026-03-02, unit: "day" }
```

The main entry is `withUnits(createUnits())`, as separate functions, so
your bundler keeps only the ones you import. Periods from both are the same
plain objects, so you can mix them.

Where the runtime has no Temporal yet (Safari, Node 24), call
[`await temporalReady()`](../../minuta-temporal/temporal-ready/) from
`@aleksejdix/minuta/temporal` once, before you compute.
