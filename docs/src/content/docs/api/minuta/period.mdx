Get the whole unit of time that a date falls in: the day of a date, its week,
its month, its year.

```ts
import { period } from "@aleksejdix/minuta";
```

```ts
period(value, unit);
```

## Example

```ts
import { period } from "@aleksejdix/minuta";

period(Temporal.PlainDate.from("2026-03-18"), "month");
// → { start: 2026-03-01, end: 2026-04-01, unit: "month" }

period(Temporal.PlainDate.from("2026-03-18"), "week");
// → { start: 2026-03-16, end: 2026-03-23, unit: "week" }
```

The value can be any date or moment inside the unit. Mar 1, Mar 18 at 14:35
and Mar 31 at 23:59 all give the same month.

where the next one starts, wherever the pin sits inside it.

## Parameters

| Name    | What it is                                                                                                       |
| ------- | ---------------------------------------------------------------------------------------------------------------- |
| `value` | A `PlainDate` or a `ZonedDateTime` inside the period you want.                                                   |
| `unit`  | The size of the period: `"year"`, `"quarter"`, `"month"`, `"week"`, `"day"`, `"hour"`, `"minute"` or `"second"`. |

## Returns

A period: a plain object with three fields.

- `start` — the first day (or moment) of the unit. It is part of the period.
- `end` — where the next unit starts. The end is _exclusive_: it is not part
  of the period, so March ends at Apr 1, and the next period starts there.
- `unit` — the unit you asked for.

For `"year"` to `"day"`, `start` and `end` are `Temporal.PlainDate`s: a day is
a date, with no time zone. For `"hour"`, `"minute"` and `"second"` they are
`Temporal.ZonedDateTime`s. See
[Periods and units](../../../concepts/periods-and-units/) for the idea behind
this shape.

## Every unit

For the moment Wed Mar 18 2026, 14:35:20.500 in Europe/Zurich:

| Unit        | `start`          | `end`            |
| ----------- | ---------------- | ---------------- |
| `"year"`    | 2026-01-01       | 2027-01-01       |
| `"quarter"` | 2026-01-01       | 2026-04-01       |
| `"month"`   | 2026-03-01       | 2026-04-01       |
| `"week"`    | 2026-03-16       | 2026-03-23       |
| `"day"`     | 2026-03-18       | 2026-03-19       |
| `"hour"`    | 2026-03-18 14:00 | 2026-03-18 15:00 |
| `"minute"`  | 2026-03-18 14:35 | 2026-03-18 14:36 |
| `"second"`  | 14:35:20         | 14:35:21         |

Weeks start on Monday here (ISO 8601). To start them on Sunday, use
`withUnits(createUnits({ weekStartsOn: "sunday" })).period(date, "week")`,
see [`withUnits`](../with-units/).

## Time zones and daylight saving

A day period holds dates, so clock changes cannot move it. Mar 29 2026, the
day the clocks jump from 2:00 to 3:00 in Europe/Zurich, is still one date:

```ts
period(Temporal.PlainDate.from("2026-03-29"), "day");
// → { start: 2026-03-29, end: 2026-03-30, unit: "day" }
```

Time units need a zone. A `ZonedDateTime` keeps its own. A `PlainDate` starts
at the beginning of its day in the units' time zone, which is the runtime's
by default.

`period` takes no `Instant` or `PlainDateTime`, so it never guesses a zone.
Give the value one first with Temporal. The zone decides the day:

```ts
const moment = Temporal.Instant.from("2026-03-18T23:35:00Z");

period(moment.toZonedDateTimeISO("Europe/Zurich"), "day");
// → { start: 2026-03-19, end: 2026-03-20, unit: "day" }
period(moment.toZonedDateTimeISO("America/New_York"), "day");
// → { start: 2026-03-18, end: 2026-03-19, unit: "day" }
```

A `PlainDateTime` gets its zone with `toZonedDateTime("Europe/Zurich")`.

To compute in a fixed time zone instead, use
`withUnits(createUnits({ timeZone: "UTC" }))`, or pass `ZonedDateTime`s in
that zone (see [`createUnits`](../create-units/)).

## There is no `"custom"` unit here

`"custom"` is the unit of periods that do not match one whole unit. You cannot
ask `period` for one; use [`range`](../range/) to make a period from any two
dates or moments.

```ts
period(Temporal.Now.plainDateISO(), "custom");
// RangeError: UNIT_NOT_SUPPORTED: no "custom" spec in the units passed …
```

## Errors

`period` throws a `RangeError` whose message starts with a code:

| Code                 | When                                                             |
| -------------------- | ---------------------------------------------------------------- |
| `UNIT_NOT_SUPPORTED` | `unit` is not one of the units listed above, e.g. `"fortnight"`. |
