---
title: period
description: Make a period between any two dates or moments, such as a meeting, a trip or a billing cycle. The start is included, the end is not.
---

import { plainDate, zonedDateTime } from "../../../../components/temporal";
import { day, period } from "@aleksejdix/minuta";
import Timeline from "../../../../components/diagrams/Timeline.astro";

export const trip = period(plainDate("2026-03-18"), plainDate("2026-03-25"));
export const wholeTrip = period(
  day(plainDate("2026-03-18")).start,
  day(plainDate("2026-03-25")).end
);

Make a period between any two dates or moments: a meeting from 9:00 to
10:00, a trip from Jan 1 to Mar 31, a billing cycle. For the whole year,
month, week or day around a value, use [`year`](../year/),
[`month`](../month/), [`week`](../week/), [`day`](../day/) and the other
unit functions instead.

```ts
import { period } from "@aleksejdix/minuta";
```

```ts
period(start, end);
```

## Example

```ts
import { period } from "@aleksejdix/minuta";

period(
  Temporal.PlainDate.from("2026-01-01"),
  Temporal.PlainDate.from("2026-04-01")
);
// → { start: 2026-01-01, end: 2026-04-01, unit: "custom" }: January to March
```

## Parameters

| Name    | What it is                                                     |
| ------- | -------------------------------------------------------------- |
| `start` | The first edge, included: a `PlainDate` or a `ZonedDateTime`.  |
| `end`   | The last edge, excluded, of the same kind. Not before `start`. |

## Returns

A period with the unit `"custom"`. `start` and `end` are the values you
passed, unchanged. `start` is part of the period, `end` is not: the end is
_exclusive_.

Two dates make a period of dates, two `ZonedDateTime`s a period of moments.
`"custom"` means "not one whole unit". See
[Periods and units](../../../concepts/periods-and-units/).

## The end is not included

`period` stops right before `end`. A period of dates that ends on Mar 31
does not include Mar 31 itself:

```ts
import { contains, count, period } from "@aleksejdix/minuta";

const q1 = period(
  Temporal.PlainDate.from("2026-01-01"),
  Temporal.PlainDate.from("2026-03-31")
);

contains(q1, Temporal.PlainDate.from("2026-03-31")); // → false
count(q1, "day"); // → 89
```

To include the whole last day, end the period at the day after it. The
`end` of a [`day`](../day/) is exactly that:

```ts
import { count, day, period } from "@aleksejdix/minuta";

const q1 = period(
  Temporal.PlainDate.from("2026-01-01"),
  day(Temporal.PlainDate.from("2026-03-31")).end
);
// → { start: 2026-01-01, end: 2026-04-01, unit: "custom" }

count(q1, "day"); // → 90
```

Custom periods are hatched because their unit is `"custom"`. The first one
stops where the last day begins; the second one ends with it.

:::tip
Because the end is excluded, back-to-back slots share a boundary: a period
from 9:00 to 10:00 is exactly one hour, and it only touches a period that
starts at 10:00. [`overlaps`](../overlaps/) says `false` for the two.
:::

## The start comes first

`period` does not swap its values. An `end` before the `start` is an error:

```ts
period(
  Temporal.PlainDate.from("2026-04-01"),
  Temporal.PlainDate.from("2025-12-01")
);
// → RangeError: period() needs the start first: 2026-04-01 is after 2025-12-01.
```

A period may start and end at the same value. It is then empty: it
contains nothing, and [`count`](../count/) gives `0`.

## Errors

- `RangeError` when `end` comes before `start`.
- `TypeError` when `start` and `end` are of different kinds, a `PlainDate`
  and a `ZonedDateTime`. Convert one first, e.g. with
  `date.toZonedDateTime(timeZone)` or `moment.toPlainDate()`.
