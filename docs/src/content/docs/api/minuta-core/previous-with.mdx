Get the period right before a period (the day, week or month before),
computed with the units you pass.

```ts
import { previousWith } from "@aleksejdix/minuta/core";
```

```ts
previousWith(units, period);
```

## Example

```ts
import { createUnits, periodWith, previousWith } from "@aleksejdix/minuta/core";

const units = createUnits({ weekStartsOn: "sunday" });
const week = periodWith(units, Temporal.PlainDate.from("2026-03-18"), "week");
// → { start: 2026-03-15, end: 2026-03-22, unit: "week" }

previousWith(units, week);
// → { start: 2026-03-08, end: 2026-03-15, unit: "week" }
```

## Parameters

| Name     | What it is                                                           |
| -------- | -------------------------------------------------------------------- |
| `units`  | The units to compute with, e.g. [`createUnits()`](../create-units/). |
| `period` | The current period.                                                  |

## Returns

A new, whole period of the same unit that ends where `period` starts.
`previousWith(units, p)` is the same as
[`shiftWith(units, p, -1)`](../shift-with/).

It works exactly like [`previous`](../../minuta/previous/), which is
`previousWith` with `createUnits()` bound. Read that page for year ends,
daylight saving and custom periods, which move by their own length.

Pass the units the period was made with; see
[`nextWith`](../next-with/#use-the-same-units-as-the-period) for why.

## Errors

`previousWith` throws a `RangeError` starting with `UNIT_NOT_SUPPORTED` when
`units` has no spec for `period.unit`.
