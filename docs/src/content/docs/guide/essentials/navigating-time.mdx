A calendar has two buttons: ‹ and ›. A week planner has them too, and so has
a report that shows "this quarter". All of them ask the same question: _what
comes after this period, and what came before?_

This page shows how minuta answers it. You need one idea from
[Periods and units](../../../concepts/periods-and-units/): a period is a
`start`, an `end` and a `unit`.

All examples run in Europe/Zurich, with weeks from Monday to Sunday.

## One step forward, one step back

Start with the month around a date. [`next`](../../../api/minuta/next/) gives
the month after it, [`previous`](../../../api/minuta/previous/) the month
before:

```ts
import { month, next, previous } from "@aleksejdix/minuta";

const march = month(Temporal.PlainDate.from("2026-03-18"));
// → { start: 2026-03-01, end: 2026-04-01, unit: "month" }

next(march);
// → { start: 2026-04-01, end: 2026-05-01, unit: "month" }

previous(march);
// → { start: 2026-02-01, end: 2026-03-01, unit: "month" }
```

You get back a whole new month, with its own length. April has 30 days,
February 28. You never count days yourself.

The period you pass is not changed. `march` is still March afterwards.

## Every unit steps by itself

`next` and `previous` take no unit. They step by the unit the period already
has: a day moves by a day, a week by a week, a year by a year.

```ts
const date = Temporal.PlainDate.from("2026-03-18");

const wednesday = day(date);
next(wednesday); //     → { start: 2026-03-19, end: 2026-03-20, unit: "day" }
previous(wednesday); // → { start: 2026-03-17, end: 2026-03-18, unit: "day" }

const thisWeek = week(date);
// → { start: 2026-03-16, end: 2026-03-23, unit: "week" }, Mon Mar 16 – Sun Mar 22
next(thisWeek);
// → { start: 2026-03-23, end: 2026-03-30, unit: "week" }

next(quarter(date));
// → { start: 2026-04-01, end: 2026-07-01, unit: "quarter" }

previous(year(date));
// → { start: 2025-01-01, end: 2026-01-01, unit: "year" }
```

The same code works for every unit. A planner that can switch between day,
week and month view does not need three ways to step.

## Build the ‹ › buttons

A calendar keeps the period it shows in its state. The buttons replace it with
its neighbour:

```ts
import { month, next, previous } from "@aleksejdix/minuta";

let shown = month(Temporal.PlainDate.from("2026-03-18")); // → March 2026

shown = next(shown); //     → April 2026
shown = next(shown); //     → May 2026
shown = previous(shown); // → April 2026
```

A "Today" button just asks for the period around the current date again:

```ts
shown = month(Temporal.Now.plainDateISO());
```

In React or Vue, `shown` is a piece of state, and each button calls a setter
with `next(shown)` or `previous(shown)`. Periods are plain objects, so they
work as state as they are.

:::tip
To show the label of the month ("April 2026"), pass `shown` to `toLocaleString`.
See [Formatting labels](../formatting/).
:::

## Jump several steps with shift

To move more than one step, use [`shift`](../../../api/minuta/shift/). A
positive number moves forward, a negative number moves back:

```ts
import { month, shift, week } from "@aleksejdix/minuta";

const march = month(Temporal.PlainDate.from("2026-03-18"));

shift(march, 3);
// → { start: 2026-06-01, end: 2026-07-01, unit: "month" }

shift(march, -14);
// → { start: 2025-01-01, end: 2025-02-01, unit: "month" }

shift(week(Temporal.PlainDate.from("2026-03-18")), -2);
// → { start: 2026-03-02, end: 2026-03-09, unit: "week" }
```

<Timeline
  caption="shift(march, -14) and shift(march, 3) land on whole months, 14 back and 3 ahead."
  tracks={[
    {
      label: "shift(march, -14)",
      periods: [shift(march, -14)],
      tone: "accent",
    },
    { label: "march", periods: [march], tone: "ink" },
    { label: "shift(march, 3)", periods: [shift(march, 3)], tone: "accent" },
  ]}
/>

`next(p)` is the same as `shift(p, 1)`, and `previous(p)` the same as
`shift(p, -1)`. `shift(p, 0)` gives back `p` itself.

"The same month last year" is `shift(month, -12)`. "Four weeks from now" is
`shift(week, 4)`.

:::caution
Pass whole numbers to `shift`. minuta does not check them: with fractions,
some units throw a `RangeError` and others round, so do not rely on them.
:::

## Month ends and leap years are safe

Stepping months by hand is a classic bug. With a plain `Date`, Jan 31 plus
one month is not in February at all:

```ts
const date = new Date(2026, 0, 31);
date.setMonth(date.getMonth() + 1);
// → Tue Mar 3 2026 (there is no Feb 31, so it overflows)
```

minuta steps whole periods, so there is no day of the month that can overflow:

```ts
next(month(Temporal.PlainDate.from("2026-01-31")));
// → { start: 2026-02-01, end: 2026-03-01, unit: "month" }
```

<Timeline
  caption="Starting from Jan 31 (the pin), next steps the whole month, so it lands on all of February, not on Mar 3."
  marks={[{ date: plainDate("2026-01-31"), label: "Jan 31" }]}
  tracks={[
    { label: "month(Jan 31)", periods: [january], tone: "ink" },
    { label: "next(…)", periods: [next(january)], tone: "accent" },
  ]}
/>

Leap years work the same way. The day after Feb 28 2028 is Feb 29, and the
February one year later has 28 days again:

```ts
next(day(Temporal.PlainDate.from("2028-02-28")));
// → { start: 2028-02-29, end: 2028-03-01, unit: "day" }

shift(month(Temporal.PlainDate.from("2028-02-10")), 12);
// → { start: 2029-02-01, end: 2029-03-01, unit: "month" }
```

## Clock changes are safe too

The next period is found on the calendar, not by adding a fixed number of
hours. In Europe/Zurich the clocks go forward on Mar 29 2026, so that day has
only 23 hours. The next day is still one date, and the hour after 1:00 is
3:00:

```ts
next(day(Temporal.PlainDate.from("2026-03-28")));
// → { start: 2026-03-29, end: 2026-03-30, unit: "day" } (23 hours long)

next(hour(Temporal.ZonedDateTime.from("2026-03-29T01:00[Europe/Zurich]")));
// → { start: 03:00, end: 04:00, unit: "hour" } (2:00 does not exist that night)
```

## Change the unit first, then step

`shift` always steps by the period's own unit. To move a day by months,
first get the month it falls in, then step:

```ts
const wednesday = day(Temporal.PlainDate.from("2026-03-18"));

shift(month(wednesday.start), 2);
// → { start: 2026-05-01, end: 2026-06-01, unit: "month" }
```

The same trick moves between views: `week(wednesday.start)` is the week of
that day, `month(thisWeek.start)` the month the week starts in.

## Custom periods move by their length

A period made with [`period`](../../../api/minuta/period/) has the unit
`"custom"`. It is not one whole unit, so there is no unit to step by.
Instead it moves by its own length:

```ts
import { next, period, previous, shift } from "@aleksejdix/minuta";

const slot = period(
  Temporal.ZonedDateTime.from("2026-03-02T09:00[Europe/Zurich]"),
  Temporal.ZonedDateTime.from("2026-03-02T10:00[Europe/Zurich]")
);
// → { start: 09:00, end: 10:00, unit: "custom" } on Mon Mar 2

next(slot); //     → { start: 10:00, end: 11:00, unit: "custom" }
previous(slot); // → { start: 08:00, end: 09:00, unit: "custom" }
shift(slot, 2); // → { start: 11:00, end: 12:00, unit: "custom" }
```

This is useful for things that have no calendar unit: a three-day trip, a
two-hour shift, a billing cycle. A trip from Friday to Sunday moves to Monday
to Wednesday:

```ts
const trip = period(
  Temporal.PlainDate.from("2026-03-13"),
  Temporal.PlainDate.from("2026-03-16")
);
// → { start: 2026-03-13, end: 2026-03-16, unit: "custom" }, Fri to Sun

next(trip);
// → { start: 2026-03-16, end: 2026-03-19, unit: "custom" }, Mon to Wed
```

<Timeline
  caption="A three-day custom trip and its next: the same three days long, starting where it ends. Hatched, because neither is one whole unit."
  tracks={[
    { label: "trip", periods: [trip], tone: "ink" },
    { label: "next(trip)", periods: [next(trip)], tone: "accent" },
  ]}
/>

A custom period of dates moves by days. One of moments moves by elapsed time, not
on the calendar, so a custom week of moments that is moved over a clock
change ends up an hour off:

```ts
next(
  period(
    Temporal.ZonedDateTime.from("2026-03-23T00:00[Europe/Zurich]"),
    Temporal.ZonedDateTime.from("2026-03-30T00:00[Europe/Zurich]")
  )
);
// → { start: 2026-03-30T00:00, end: 2026-04-05T23:00, unit: "custom" }
```

The pieces at the edges of a [`divide`](../dividing-time/) are often custom
too. The first piece of March split into weeks is just Sun Mar 1, so its
`next` is Mon Mar 2, not the next week. To step by whole weeks, step
`week(piece.start)` instead.
