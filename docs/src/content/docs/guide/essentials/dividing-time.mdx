export const meeting = range(
  zonedDateTime("2026-03-18T09:10[Europe/Zurich]"),
  zonedDateTime("2026-03-18T10:40[Europe/Zurich]")
);

Most date screens are lists: the days of a month, the hours of a day, the
time slots someone can book. Each of them is one period split into smaller
ones. [`divide`](../../../api/minuta/divide/) does that split.

All examples run in Europe/Zurich, with weeks from Monday to Sunday.

## The days of this month

Get the month, then divide it into days:

```ts
import { divide, period } from "@aleksejdix/minuta";

const march = period(Temporal.PlainDate.from("2026-03-18"), "month");
const days = divide(march, "day");

days.length; // → 31
days[0]; //     → { start: 2026-03-01, end: 2026-03-02, unit: "day" }
days.at(-1); // → { start: 2026-03-31, end: 2026-04-01, unit: "day" }
```

Each piece is a full period, so everything else works on it: you can label it,
check it with `contains`, or step from it with `next`.

The pieces are in order and cover the month exactly. Each one ends where the
next one starts, so there are no gaps and no overlaps.

## Any period, any smaller unit

The same call works for every pair of units:

```ts
const date = Temporal.PlainDate.from("2026-03-18");

divide(period(date, "day"), "hour").length; //   → 24
divide(period(date, "year"), "month").length; // → 12
divide(period(date, "year"), "quarter");
// → [2026-01-01, 2026-04-01), [2026-04-01, 2026-07-01),
//   [2026-07-01, 2026-10-01), [2026-10-01, 2027-01-01), unit "quarter"
```

The pieces are real calendar units. On the nights the clocks change, a day has
23 or 25 hours, and `divide` gives you exactly those. A day has no time
zone; its hours are moments in the units' zone (here Europe/Zurich):

```ts
divide(period(Temporal.PlainDate.from("2026-03-29"), "day"), "hour").length; // → 23
divide(period(Temporal.PlainDate.from("2026-10-25"), "day"), "hour").length; // → 25
```

:::tip
To only count the pieces, not make them, use
[`duration`](../../../api/minuta/duration/): `duration(march, "day")` is `31`.
See [Comparing and measuring](../comparing-and-measuring/).
:::

## Slots with step

A booking page shows slots of 15 or 30 minutes. Pass `step` to make each piece
span several units:

```ts
const day = period(Temporal.PlainDate.from("2026-03-18"), "day");
const slots = divide(day, "minute", { step: 15 });

slots.length; // → 96
slots[0]; //     → { start: 00:00, end: 00:15, unit: "custom" }
slots[1]; //     → { start: 00:15, end: 00:30, unit: "custom" }
slots.at(-1); // → { start: 23:45, end: 00:00 on Mar 19, unit: "custom" }
```

The slots have the unit `"custom"`, because 15 minutes is not one whole unit.
Pieces made with a `step` above 1 are always custom, even when they happen to
line up with a calendar unit:

```ts
divide(period(Temporal.PlainDate.from("2026-03-18"), "year"), "month", {
  step: 3,
})[0];
// → { start: 2026-01-01, end: 2026-04-01, unit: "custom" }
```

If you want real quarters, divide by `"quarter"` instead.

## Only the opening hours

You often want slots for part of a day, such as 9:00 to 17:00. Make that part
with [`range`](../../../api/minuta/range/), then divide it:

```ts
import { divide, range } from "@aleksejdix/minuta";

const open = range(
  Temporal.ZonedDateTime.from("2026-03-18T09:00[Europe/Zurich]"),
  Temporal.ZonedDateTime.from("2026-03-18T17:00[Europe/Zurich]")
);

divide(open, "hour");
// → 8 periods: 9:00–10:00, 10:00–11:00, … 16:00–17:00, unit "hour"
```

A range does not include its end, so a range up to 17:00 ends with the hour
from 16:00. There is no extra piece at 17:00.

## Weeks of a month: the edges are cut

Weeks and months don't line up. When you divide March into weeks, the first
and last weeks stick out into February and April. `divide` never gives you a
piece outside the period you split, so it cuts those two at the month's edges
and marks them `"custom"`:

```ts
divide(march, "week");
// → Sun Mar 1          "custom"  (the week started in February)
//   Mon Mar 2 – Sun 8  "week"
//   Mon Mar 9 – Sun 15 "week"
//   Mon Mar 16 – Sun 22 "week"
//   Mon Mar 23 – Sun 29 "week"
//   Mon Mar 30 – Tue 31 "custom"  (the week ends in April)
```

This is what you want for "how much of each week falls in this month", for
example a monthly report with one row per week.

The same happens when the start of the period is not on a unit border. A
meeting from 9:10 to 10:40 divided by hour gives two cut pieces:

```ts
divide(
  range(
    Temporal.ZonedDateTime.from("2026-03-18T09:10[Europe/Zurich]"),
    Temporal.ZonedDateTime.from("2026-03-18T10:40[Europe/Zurich]")
  ),
  "hour"
);
// → 9:10 – 10:00  "custom"
//   10:00 – 10:40 "custom"
```

## Weeks of a month: whole weeks

A calendar view wants the opposite: whole weeks that cover the month, from the
Monday before the 1st to the Sunday after the 31st. Make that span from the
week of the first day and the week of the last day, then divide it. The last
day is the day before `march.end`, because the end is excluded:

```ts
import { divide, period, range } from "@aleksejdix/minuta";

const lastDay = march.end.subtract({ days: 1 }); // → 2026-03-31

const weeks = divide(
  range(period(march.start, "week").start, period(lastDay, "week").end),
  "week"
);
// → Mon Feb 23 – Sun Mar 1   "week"
//   Mon Mar 2  – Sun Mar 8   "week"
//   …
//   Mon Mar 30 – Sun Apr 5   "week"   (6 whole weeks)
```

Every piece is now a whole `"week"`, so `next` steps them by a week.

## Dividing by a bigger unit

If the unit is not smaller than the period, you get one piece. A month divided
by month is that month; a day divided by month is the day, marked custom
because it is not a whole month:

```ts
divide(march, "month");
// → [{ start: 2026-03-01, end: 2026-04-01, unit: "month" }]

divide(period(Temporal.PlainDate.from("2026-03-18"), "day"), "month");
// → [{ start: 2026-03-18, end: 2026-03-19, unit: "custom" }]
```

## The safety limit

A year split into seconds would be over 31 million objects. `divide` stops
long before that: by default it throws once it would make more than
100 000 pieces.

```ts
divide(period(Temporal.PlainDate.from("2026-01-01"), "year"), "second");
// RangeError: TOO_MANY_PERIODS: divideWith() generated over 100000 periods. …
```

Set your own limit with `maxPeriods`, lower to protect a screen, or higher
when you really need more:

```ts
divide(period(Temporal.PlainDate.from("2026-01-01"), "year"), "minute", {
  maxPeriods: 1000,
});
// RangeError: TOO_MANY_PERIODS: divideWith() generated over 1000 periods. …
```

`step` and `maxPeriods` must be positive whole numbers. `{ step: 0 }` or
`{ step: 1.5 }` throws a `RangeError` with the code `INVALID_OPTION`.

## Calendar grids are the next step

A month view in a calendar is a grid: always six rows of seven days, starting
on the first day of the week, with the days of the months around it filled
in. You could build it with `divide`, but
[`@aleksejdix/minuta/calendar`](../../../api/minuta-calendar/overview/) does it for you,
and follows your week start:

```ts
import { monthGridWith } from "@aleksejdix/minuta/calendar";
import { createUnits } from "@aleksejdix/minuta/core";

const grid = monthGridWith(
  createUnits(),
  Temporal.PlainDate.from("2026-03-18")
);

grid.periods.length; // → 42
grid.periods[0]; //     → { start: 2026-02-23, end: 2026-02-24, unit: "day" }, a Monday
grid.periods.at(-1); // → { start: 2026-04-05, end: 2026-04-06, unit: "day" }, a Sunday
```

See [Weeks and calendars](../../../concepts/weeks-and-calendars/) for grids,
week start and weekends.
