A week looks simple, but countries disagree about it. In Switzerland the
week starts on Monday, in the US on Sunday, in Egypt on Saturday. The
weekend is Saturday and Sunday in most places, but Friday and Saturday in
others. minuta lets you set both, and builds calendar grids that follow
them.

## See the problem

Switch the locale, the week start and the weekend. The hand-made grid on top never changes; the minuta grid below follows the settings. With **ar-EG** the locale starts weeks on Saturday with a Friday–Saturday weekend (in browsers that support `Intl.Locale#getWeekInfo`).

## Week start

The week start decides where every `"week"` period begins. It is a setting
of the **units**, chosen when you create them:

```ts
import { createUnits, withUnits } from "@aleksejdix/minuta/core";

const monday = withUnits(createUnits());
const sunday = withUnits(createUnits({ weekStartsOn: "sunday" }));

monday.period(Temporal.PlainDate.from("2026-03-18"), "week");
// → { start: 2026-03-16, end: 2026-03-23, unit: "week" }, Monday to Sunday
sunday.period(Temporal.PlainDate.from("2026-03-18"), "week");
// → { start: 2026-03-15, end: 2026-03-22, unit: "week" }, Sunday to Saturday
```

- The default is **Monday**, as in the ISO 8601 standard.
- Name the day in lowercase English (`"sunday"` … `"saturday"`), or use a
  number: 0 = Sunday, 1 = Monday … 6 = Saturday.
- The units store it as a number: `createUnits({ weekStartsOn: "sunday" }).weekStartsOn`
  is `0`.
- The default `minuta` entry (`import { period } from "@aleksejdix/minuta"`) always
  starts weeks on Monday. For another start, use `withUnits` from
  `@aleksejdix/minuta/core`.

minuta never reads the week start from a locale on its own.

Everything that deals with weeks follows it: `period(date, "week")`,
`divide(month, "week")`, `next` and `previous` of a week, month and year
grids, `snapWith(units, date, "week")`, and whether `mergeWith` calls seven
days a `"week"`.

## Weekend

The weekend is a second setting of the units. It is used by exactly two
functions, [`isWeekendWith`](../../api/minuta-calendar/is-weekend-with/) and
[`isWeekdayWith`](../../api/minuta-calendar/is-weekday-with/):

```ts
import { isWeekendWith } from "@aleksejdix/minuta/calendar";
import { period } from "@aleksejdix/minuta";
import { createUnits } from "@aleksejdix/minuta/core";

const units = createUnits({ weekend: ["friday", "saturday"] });

isWeekendWith(units, period(Temporal.PlainDate.from("2026-03-20"), "day")); // → true  (Friday)
isWeekendWith(units, period(Temporal.PlainDate.from("2026-03-22"), "day")); // → false (Sunday)
```

- The default is Saturday and Sunday.
- Any list of days works, also one day or none (`weekend: []`).
- The weekend does not change grids or weeks. Mark weekend cells yourself
  with `isWeekendWith`.
- minuta knows nothing about public holidays.

## Taking both from the user's locale

minuta does not guess the week start or the weekend from a locale. Where the
runtime supports it, `Intl.Locale#getWeekInfo()` tells you. It numbers days
1 = Monday … 7 = Sunday, so turn 7 into 0:

```ts
const info = new Intl.Locale("en-US").getWeekInfo();
// → { firstDay: 7, weekend: [6, 7] }

const units = createUnits({
  weekStartsOn: info.firstDay % 7, // → 0, Sunday
  weekend: info.weekend.map((day) => day % 7), // → [6, 0]
});
```

With `"ar-EG"` this gives weeks starting on Saturday and a Friday–Saturday
weekend. `getWeekInfo` is not available in every browser yet.

## Week numbers

minuta does not compute week numbers. In particular, the position of a week
in [`yearGridWith`](../../api/minuta-calendar/year-grid-with/) is not the
ISO week number: the grid starts with the week that contains January 1,
while ISO week 1 is the week that contains the first Thursday. For 2021,
the grid's first week (Mon Dec 28 2020) is ISO week 53 of 2020. For the
ISO week number of a date, Temporal has it: `date.weekOfYear`.

## Calendar grids

[`@aleksejdix/minuta/calendar`](../../api/minuta-calendar/overview/) builds the data
for calendar screens. Every cell is an ordinary period.

| Grid                                                          | What it is                                                          |
| ------------------------------------------------------------- | ------------------------------------------------------------------- |
| [`monthGridWith`](../../api/minuta-calendar/month-grid-with/) | Always 42 days: 6 weeks of 7, from the week start before the 1st.   |
| [`yearGridWith`](../../api/minuta-calendar/year-grid-with/)   | Whole weeks from the week of Jan 1 to the week of Dec 31: 53 or 54. |
| [`dayGridWith`](../../api/minuta-calendar/day-grid-with/)     | The real hours of a day: 23, 24 or 25.                              |

The month grid always has 42 days, even for a February that fits into 4
rows. A month view built on it keeps the same height for every month, so
nothing jumps when the user pages through months.

```ts
import { monthGridWith } from "@aleksejdix/minuta/calendar";

const march = Temporal.PlainDate.from("2026-03-15");

monthGridWith(createUnits(), march).periods[0].start;
// → 2026-02-23, a Monday (the week of Mar 1 starts on Monday)

monthGridWith(createUnits({ weekStartsOn: "sunday" }), march).periods[0].start;
// → 2026-03-01, a Sunday (March 2026 starts on a Sunday)
```

Month and year grids are made of dates, so they have no time zone. The day
grid's hours are moments in the units' time zone, see
[Time zones](../time-zones/).

## Calendar systems

minuta computes with the **Gregorian calendar** only: months are January to
December, years are Gregorian years (the ISO 8601 calendar of Temporal).

Other calendar systems are available for **labels**, through the locale of
[`formatPeriod`](../../api/minuta-format/format-period/) and
`formatRange`. Add `-u-ca-` and a calendar name to the locale:

```ts
import { formatPeriod } from "@aleksejdix/minuta/format";

formatPeriod(
  period(Temporal.PlainDate.from("2026-03-15"), "month"),
  "en-US-u-ca-buddhist"
);
// → "March 2569 BE"
```

The period is still the Gregorian month. In calendars whose months start on
other days, the label names the month in which the period **starts**: March
2026 in `"fa-IR"` (Persian calendar) is labelled "۱۴۰۴ اسفند" (Esfand 1404),
although March 21–31 already fall in the next Persian month, Farvardin 1405.
