minuta does not hard-code what a week or a month is. It asks the **units**:
a small set of rules for each unit of time, computed with
[Temporal](https://tc39.es/proposal-temporal/docs/).

## See the idea

The same code, the same month, two sets of units: one with weeks from
Monday, one with weeks from Sunday. Only the units change, and every week
moves with them:

## Units are rules, as data

For every unit (`"day"`, `"week"`, `"month"` …) minuta needs three answers:

- `startOf(value)` — where does the unit containing `value` start?
- `add(value, amount)` — what is `amount` units later?
- `diff(from, to)` — how many whole units fit in between?

A period ends where the next one starts, so there is no `endOf`.

These three functions, plus a `kind`, are a _unit spec_. Date units
(`"year"` … `"day"`) have `kind: "date"` and work on `PlainDate`s. Time
units (`"hour"`, `"minute"`, `"second"`) have `kind: "time"` and work on
`ZonedDateTime`s. A set of specs, one per unit, plus a few settings, is
called **units**. It is a plain object:

```ts
import { createUnits } from "@aleksejdix/minuta/core";

const units = createUnits();

Object.keys(units);
// → ["day", "hour", "minute", "month", "quarter", "second",
//    "timeZone", "week", "weekStartsOn", "weekend", "year"]

units.week.startOf(Temporal.PlainDate.from("2026-03-18"));
// → 2026-03-16, a Monday
```

The settings travel with the specs:

| Setting        | What it is                                                                    |
| -------------- | ----------------------------------------------------------------------------- |
| `weekStartsOn` | The first day of the week, as a number: 0 = Sunday … 6 = Saturday.            |
| `weekend`      | The weekend days, as numbers. Saturday and Sunday unless you set it.          |
| `timeZone`     | Where dates become moments, e.g. `"Europe/Zurich"`. The runtime's by default. |

## `createUnits` makes units

[`createUnits`](../../api/minuta-core/create-units/) makes units with your
settings. Days are named (`"sunday"`), and the numbers 0 = Sunday …
6 = Saturday work too:

```ts
import { createUnits } from "@aleksejdix/minuta/core";

createUnits({
  timeZone: "America/New_York",
  weekStartsOn: "sunday",
  weekend: ["friday", "saturday"],
});
```

Every option is optional: weeks start on Monday, the weekend is Saturday
and Sunday, and the time zone is the runtime's.

Periods are always plain objects: `PlainDate`s in `start` and `end` for date
units, `ZonedDateTime`s for time units.

## `minuta`: ready to use

The main entry, [`minuta`](../../api/minuta/overview/), has
`createUnits()` built in: weeks from Monday, the runtime's time zone. There
is nothing to set up:

```ts
import { period } from "@aleksejdix/minuta";

period(Temporal.PlainDate.from("2026-03-18"), "week");
// → { start: 2026-03-16, end: 2026-03-23, unit: "week" }
```

Use it when Monday weeks and the runtime's zone are what you need.

## `@aleksejdix/minuta/core`: bring your own units

[`@aleksejdix/minuta/core`](../../api/minuta-core/overview/) has the same operations
without units built in. There are two ways to use it.

**Bind once with `withUnits`.** You get an object with every operation, all
using your units. This is the usual way:

```ts
import { createUnits, withUnits } from "@aleksejdix/minuta/core";

const time = withUnits(createUnits({ weekStartsOn: "sunday" }));

time.period(Temporal.PlainDate.from("2026-03-18"), "week");
// → { start: 2026-03-15, end: 2026-03-22, unit: "week" }
```

**Pass the units to each call.** Every unit-aware function has a `…With`
form that takes the units first. Pass only the units you use:

```ts
import { createUnits, nextWith, periodWith } from "@aleksejdix/minuta/core";

const { day, month } = createUnits();
const units = { day, month };

nextWith(
  units,
  periodWith(units, Temporal.PlainDate.from("2026-03-18"), "month")
);
// → { start: 2026-04-01, end: 2026-05-01, unit: "month" }

periodWith(units, Temporal.PlainDate.from("2026-03-18"), "week");
// RangeError: UNIT_NOT_SUPPORTED: no "week" spec in the units passed (available: day, month). …
```

See [`withUnits`](../../api/minuta-core/with-units/) and
[`periodWith`](../../api/minuta-core/period-with/).

## Another time zone

Date periods have no zone. The `timeZone` is used where dates become
moments: when a day is divided into hours, or an `Instant` becomes a
period. Here a day is split in New York, even on a server in Europe:

```ts
import { createUnits, withUnits } from "@aleksejdix/minuta/core";

const newYork = withUnits(createUnits({ timeZone: "America/New_York" }));

const day = newYork.period(Temporal.PlainDate.from("2026-03-08"), "day");
// → { start: 2026-03-08, end: 2026-03-09, unit: "day" }

newYork.duration(day, "hour"); // → 23, the clocks go forward in New York that day
```

See [Time zones](../time-zones/) for more.

## Calendar and intervals use the same units

Calendar grids ([`@aleksejdix/minuta/calendar`](../../api/minuta-calendar/overview/)) and interval helpers
([`@aleksejdix/minuta/intervals`](../../api/minuta-intervals/overview/))
bind to the same units, with `calendar(units)` and `intervals(units)`, so
they use the same week start, weekend and time zone as everything else:

```ts
import { calendar } from "@aleksejdix/minuta/calendar";
import { createUnits } from "@aleksejdix/minuta/core";

const grids = calendar(createUnits({ weekStartsOn: "sunday" }));

grids.monthGrid(Temporal.PlainDate.from("2026-03-18")).periods[0].start;
// → 2026-03-01, the grid starts on a Sunday
```

## Other calendars

Units read dates in the calendar each date carries, or in the one you set:
`createUnits({ calendar: "hebrew" })`. Months, years, quarters and grids
then follow that calendar. See [Calendar systems](../calendar-systems/).

## Your own units

Units are plain data, so you can add one. Give it a `kind` and the three
functions, and put it next to the built-in units. This fortnight counts
two-week blocks from Monday, January 5, 2026:

```ts
import { createUnits, nextWith, periodWith } from "@aleksejdix/minuta/core";
import type { DateSpec } from "@aleksejdix/minuta/core";

const base = createUnits();
const anchor = Temporal.PlainDate.from("2026-01-05");

const fortnight: DateSpec = {
  kind: "date",
  startOf: (date) => {
    const weeks = base.week.diff(anchor, base.week.startOf(date));
    return base.week.add(anchor, Math.floor(weeks / 2) * 2);
  },
  add: (date, amount) => base.week.add(date, amount * 2),
  diff: (from, to) => Math.trunc(base.week.diff(from, to) / 2),
};

const units = Object.assign({ fortnight }, base);

const sprint = periodWith(
  units,
  Temporal.PlainDate.from("2026-03-18"),
  "fortnight"
);
// → { start: 2026-03-16, end: 2026-03-30, unit: "fortnight" }

nextWith(units, sprint).start; // → 2026-03-30
```

In TypeScript, add the name and its kind to `UnitRegistry`, so
`"fortnight"` is accepted as a unit:

```ts
declare module "@aleksejdix/minuta/core" {
  interface UnitRegistry {
    fortnight: "date";
  }
}
```

:::note
`diff` must count _complete_ units, rounded toward zero, the same way `add`
steps. The built-in units guarantee this; your own units must follow it
too, or `duration` gives wrong counts.
:::

## Keep one set of units

A period does not remember which units made it. Use the same units from
start to finish. Moving a Monday week with Sunday units gives a Sunday week
(see [`nextWith`](../../api/minuta-core/next-with/#use-the-same-units-as-the-period)).
Binding once with `withUnits`, in one module that the rest of the app imports,
is the simplest way to keep them consistent.
